# 제안서 품질 검토

## 개요
제안팀이 작성한 기술·가격 제안서를 발주기관에 제출하기 전, 요구사항 충족 여부·가격 타당성·리스크 요소를 체크리스트로 점검한다. 부실한 제안서가 그대로 제출되어 탈락하거나, 가격·조건상의 리스크가 뒤늦게 발견되는 것을 방지하는 것이 목적이다.

## 사용 시점
- 제안팀이 제안서 초안 작성을 완료해 제출 전 내부 승인이 필요할 때
- 제안서가 반려되어 재작성 후 다시 검토받을 때

## 입력 / 사전 조건
- 제안서 내용(기술·가격 제안)
- 원 RFP의 요구사항 요약

## 산출물
- 승인 여부 (승인/반려)
- (반려 시) 반려 사유

## 절차
### 1. 요구사항 충족 여부 대조
RFP 요구사항 요약의 각 항목이 제안서에 빠짐없이 반영됐는지 확인한다.

### 2. 기술 제안 타당성 검토
제시된 기술 방식(온톨로지 설계, 통합 방식 등)이 실제로 구현 가능하고 일정 내 완료 가능한지 점검한다.

### 3. 가격 제안 검토
가격이 원가·마진 기준에 맞는지, 경쟁력이 있는지 확인한다.

### 4. 리스크 요소 점검
계약 조건, 일정, 책임 범위 중 회사에 불리하거나 모호한 조항이 있는지 확인한다.

### 5. 승인/반려 결정
위 점검을 통과하면 승인, 하나라도 심각한 문제가 있으면 반려하고 구체적 반려 사유를 남긴다.

## 실전 예시
### 예시 1: 승인
- 입력: 요구사항 5개 항목 모두 반영, 기술 방식 실현 가능, 가격 원가율 적정
- 산출: 승인 여부 = 승인

### 예시 2: 반려
- 입력: 요구사항 중 데이터 마이그레이션 범위 누락, 납기 산정 근거 불명확
- 산출: 승인 여부 = 반려, 반려 사유 = "데이터 마이그레이션 범위 미반영, 납기 근거 보완 필요"

## 주의사항
- 반려 시 사유는 재작성팀이 바로 수정할 수 있도록 구체적으로 남긴다.
- 가격 리스크는 재무 담당과 교차 확인이 필요할 수 있다.
