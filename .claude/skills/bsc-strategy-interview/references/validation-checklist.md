# 전략맵 품질 검증 체크리스트

Mermaid.js 전략맵을 최종 확정하기 전, 아래 4가지 설계 오류 패턴을 반드시
자체 점검하고 보정한다. 하나라도 위반하면 최종 승인 질문으로 넘어가지 않는다.

## 1. 인과적 미아 목표 (고립 노드)

**증상**: 다른 어떤 목표와도 화살표로 연결되지 않은 목표가 존재.

**보정 규칙**: 즉시 경고하고, 어느 상위/하위 목표와 연결되어야 하는지 사용자에게
되묻는다. 연결점을 찾지 못하면 그 목표는 전략맵에서 제외하고 별도 "추후 검토
과제"로 분리할지 확인한다.

## 2. 운영 태스크의 전략 목표 오인

**증상**: "CRM 솔루션 구매", "콜센터 용역 계약" 같은 일회성 태스크·프로젝트가
전략 목표로 잘못 지정됨.

**보정 규칙**: 상위 목적 위주로 목표명을 재정의한다. 예: "CRM 솔루션 구매" →
"고객 데이터 기반 개인화 대응 역량 확보". 재정의 후 그 태스크는 전략 목표가
아니라 해당 목표를 달성하기 위한 Initiative(실행 과제)로 재분류한다.

## 3. 일방향 흐름 단절

**증상**: 화살표가 하부 관점(학습·성장)에서 상부 관점(재무)으로 순차 이동하지
않고, 루프를 돌거나 거꾸로(재무 → 학습·성장) 흐름.

**보정 규칙**: 학습과 성장 → 내부 프로세스 → 고객 → 재무의 상향 단방향 흐름만
허용한다. 역행 화살표나 순환 구조를 발견하면 완벽히 차단하고, 어느 쪽 목표를
재정의하거나 관점을 재배치해야 하는지 사용자와 함께 정리한다.

## 4. 정량 측정 불가능 목표

**증상**: 성과지표(KPI)가 누락되어 진척을 측정할 수 없는 추상적 목표가 존재.

**보정 규칙**: 반드시 한 쌍(선행 지표 + 후행 지표)의 KPI 지정을 강제한다. 둘 중
하나라도 없으면 [socratic-questions.md](socratic-questions.md)의 1단계(용어
명확화)로 돌아가 정량 지표를 도출한다.

## 점검 실행 순서

1. 전략맵의 모든 노드를 나열하고, 각 노드에 최소 1개의 입력 또는 출력 화살표가
   있는지 확인한다 (1번 규칙).
2. 각 노드명이 "구매/계약/도입/설치" 같은 일회성 행위 동사로 끝나지 않는지
   확인한다 (2번 규칙).
3. 모든 화살표를 학습·성장 → 프로세스 → 고객 → 재무 순서로 정렬했을 때 역행
   또는 순환이 없는지 확인한다 (3번 규칙).
4. 각 노드에 선행·후행 KPI가 한 쌍씩 매핑되어 있는지 확인한다 (4번 규칙).
5. 4가지 모두 통과하면 사용자에게 결과를 요약해 보여주고 최종 승인을 구한다.
   하나라도 실패하면 실패 항목과 해당 노드를 구체적으로 짚어 재작업을 요청한다.
