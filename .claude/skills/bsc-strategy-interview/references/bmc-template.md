# 비즈니스 모델 캔버스(BMC) 출력 형식 및 BSC 매핑 규칙

BMC 전체조망식·혼합형 인터뷰에서 채운 9블록을 정리할 때, 그리고 BSC 하향식으로
얻은 전략맵을 사후적으로 BMC 캔버스에 역매핑할 때 모두 이 형식을 따른다.
Mermaid는 쓰지 않는다 — BMC의 물리적 9블록 배치는 그래프가 아니라 그리드이므로
Mermaid 문법으로 잘 표현되지 않는다.

## 출력 surface 선택

- **Claude Code(Artifact 도구 사용 가능)**: `Artifact` 도구로 HTML/CSS 그리드
  기반 캔버스를 렌더링한다. 실제 Strategyzer 캔버스처럼 KP·CS는 세로로 긴
  블록, VP는 가운데 강조 블록, KA/KR과 CR/CH는 각각 한 컬럼에서 위아래로
  분리, 맨 아래에 비용구조·수익원을 배치하는 `grid-template-areas`를 쓴다.
  코드를 쓰기 전 `artifact-design` 스킬을 먼저 로드해 팔레트·타이포를 이
  주제(온톨로지·그래프 등 해당 회사의 정체성)에 맞게 고른다.
  - **클러스터별 점진적 렌더링.** 9블록을 한 번에 다 채운 뒤 마지막에
    렌더링하지 않는다. bmc-questions.md의 클러스터 1개가 끝날 때마다 그
    시점까지 채워진 블록만 반영해 `Artifact`를 같은 파일 경로로 재호출
    (redeploy)한다 — 아직 답변받지 못한 블록은 빈 자리로 두거나 옅은
    "(대기 중)" 플레이스홀더로 표시해, 경영자가 클러스터를 답할 때마다
    캔버스가 실시간으로 채워지는 것을 보게 한다. 마지막 클러스터가 끝나면
    전체가 채워진 최종본으로 한 번 더 재배포한다.
- **process-gpt 채팅(deepagents) 등 Artifact 도구가 없는 환경**: 아래
  Markdown 표 템플릿으로 대체한다. Miro/Notion 등에 붙여넣었을 때 원래
  캔버스 모양을 그런대로 보존한다.

## Markdown 대체 템플릿 (Artifact 미사용 환경)

```markdown
| 🤝 핵심 파트너십<br/>(Key Partners) | ⚙️ 핵심 활동<br/>(Key Activities) | 💎 가치 제안<br/>(Value Propositions) | 🤗 고객 관계<br/>(Customer Relationships) | 👥 고객 세그먼트<br/>(Customer Segments) |
|---|---|---|---|---|
| <파트너 1><br/><파트너 2> | <활동 1><br/><활동 2> | <가치 제안 1><br/><가치 제안 2> | <관계 방식 1> | <세그먼트 1><br/><세그먼트 2> |
|  | 🔑 핵심 자원<br/>(Key Resources) |  | 🚚 채널<br/>(Channels) |  |
|  | <자원 1><br/><자원 2> |  | <채널 1> |  |

| 💰 비용 구조 (Cost Structure) | 📈 수익원 (Revenue Streams) |
|---|---|
| <비용 항목 1><br/><비용 항목 2> | <수익원 1(비중 %)><br/><수익원 2(비중 %)> |
```

## 작성 규칙

- 각 블록은 명사구 또는 짧은 서술형 3~5개 항목으로 압축한다. 문단식 설명 금지.
- 수익원·비용 항목은 가능하면 비중(%)이나 규모(금액)를 함께 표기한다.
- [references/business-model-patterns.md](business-model-patterns.md)의 패턴은
  블록이 비어 있거나 사용자가 막막해할 때만 "예시 카드"로 제시한다 — 먼저
  들이밀지 않는다.
- BMC는 완결된 서술이 아니라 스케치다. 확정 전이면 각 항목 앞에 "(가설)"을
  붙여 미확정임을 표시한다.

## BMC 9블록 ↔ BSC 4관점 매핑 규칙

BMC는 "사업이 무엇인가"를, BSC는 "그 사업을 어떻게 실행·측정하는가"를 다룬다.
아래 매핑으로 한쪽에서 다른 쪽을 도출하거나 정합성을 검증한다.

| BMC 블록 | 대응 BSC 관점(경영자 지향 용어) | 매핑 논리 |
|---|---|---|
| 수익원, 비용 구조 | 궁극적 재무 성과 (F) | 수익원의 규모·비중이 F 노드의 목표 수치 원천, 비용 구조는 수익성 KPI(마진율 등)의 근거 |
| 고객 세그먼트, 가치 제안, 채널, 고객 관계 | 고객 가치 및 관계 (C) | 가치 제안이 왜 그 세그먼트가 지갑을 여는지의 답, 채널·고객관계가 획득/유지 방식 |
| 핵심 활동, 핵심 파트너십 | 핵심 운영 역량 (P) | 가치 제안을 실제로 만들어내고 전달하는 내부·외부 운영 실행이 P 노드 |
| 핵심 자원(특히 인적 역량·기술·문화) | 조직 지속 가능성 및 성장 엔진 (L) | 핵심 활동을 지속적으로 잘 해내기 위해 축적해야 하는 역량·인프라가 L 노드 |

## 매핑 사용 방향

1. **BMC → BSC 초안 추출** (BMC 전체조망식·혼합형에서 사용): 채워진 9블록을
   위 표대로 묶어 4관점 후보 목표를 즉석 생성한다. 이후 [SKILL.md](../SKILL.md)의
   2단계(상세 구체화)로 넘겨 인과 사슬과 선행·후행 KPI 쌍을 확정한다.
2. **BSC → BMC 역매핑** (BSC 하향식에서 사용): 확정된 F/C/P/L 노드를 위 표의
   역방향으로 분류해 9블록에 채운다. 인터뷰에서 다루지 않아 채울 수 없는 블록
   (전형적으로 채널, 핵심 파트너십, 비용 구조가 누락되기 쉽다)은 빈 칸으로 두지
   않고 "(미확인 — 추후 보완 필요)"로 명시한 뒤, 사용자에게 한 번에 하나씩만
   짧게 보완 질문을 던져 채운다.
3. 두 방향 모두, 완성 후 F 노드의 재무 목표 수치와 수익원 블록의 합계가
   일치하는지, C 노드의 가치 제안과 BMC 가치 제안 블록이 같은 이야기를 하는지
   교차 검증한다. 불일치가 발견되면 침묵하지 말고 어느 쪽이 최신 정보인지
   사용자에게 확인한다.
