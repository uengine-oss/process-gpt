# 09 – Document Intake: 업로드 문서로 프로세스 생성

**목적**: 사용자가 **문서를 업로드/첨부하거나 파일 경로를 제시**한 경우, 그 문서의 내용을 읽어 **있는 그대로의 업무 흐름(as-is)** 을 추출하고, 이를 컨설팅(1단계)의 흐름 초안으로 삼는다. 흐름을 추측하지 않고 **문서 근거로** 만든다는 점이 핵심이다.

> 이것은 pdf2bpmn 의 본래 출발점(업무 규정·매뉴얼 PDF → BPMN)을 이 skill 안으로 가져온 것입니다. 문서가 있으면 컨설팅 품질이 크게 올라가므로, 문서 신호가 보이면 **반드시 먼저 읽고** 진행합니다.

---

## 1. 언제 이 단계를 타나 (문서 신호 감지)

다음 중 하나라도 해당하면 문서 기반 모드로 진입한다:

- 사용자가 파일을 **첨부/업로드**했다 (대화에 파일·이미지가 함께 옴).
- 사용자가 **파일 경로/이름**을 언급한다. 예: "이 매뉴얼대로 만들어줘", `C:\...\업무규정.pdf`, "첨부한 SOP 보고", "이 양식 기준으로".
- 사용자가 **긴 절차 텍스트를 붙여넣었다** (규정·매뉴얼·이메일 스레드 등). 이 경우도 "문서"로 취급해 아래 추출 규칙을 적용한다.

문서 신호가 없으면 이 단계는 건너뛰고 평소대로 [01-consulting.md](01-consulting.md) 의 "초안을 먼저 제안" 으로 간다.

---

## 2. 문서 읽기 (형식별)

| 형식 | 읽는 방법 |
|------|----------|
| `.pdf` | **Read** 도구로 읽는다(`pages` 파라미터로 범위 지정, 10쪽 초과면 분할). 스캔본(이미지 PDF)이라 텍스트가 안 나오면 페이지를 이미지로 읽어 내용을 파악하거나, `anthropic-skills:pdf` 의 OCR 을 활용한다. |
| `.docx` | `anthropic-skills:docx` 로 본문/표를 추출하거나, 텍스트가 충분하면 Read 로 직접. |
| `.xlsx`/`.csv` | `anthropic-skills:xlsx` 로 표를 읽는다. 절차가 행으로 나열된 표(단계/담당/조건 열)는 그대로 흐름의 뼈대가 된다. |
| `.pptx` | `anthropic-skills:pptx` 로 슬라이드 텍스트를 추출. |
| 이미지(`.png`/`.jpg`, 흐름도·양식 사진) | **Read** 로 이미지를 직접 보고(비전) 흐름/항목을 파악한다. |
| `.txt`/`.md`/붙여넣은 텍스트 | 그대로 분석. |

> 여러 파일이면 모두 읽고 종합한다. 핵심 문서가 무엇인지 모호하면 사용자에게 "어느 문서를 기준으로 할까요?" 한 번만 확인한다.

> **여러 프로세스 감지 (중요)**: 문서를 읽고 나서 그 안에 **독립된 프로세스가 2개 이상**(서로 다른 절차/SOP, 각자 독립된 시작·종료·목적)이거나, **여러 문서가 각각 다른 프로세스**이면 — 한 흐름으로 뭉뚱그리지 말고 [11-multi-process.md](11-multi-process.md) 로 가서 **프로세스 인벤토리(번호 목록) → 범위·진행방식 확정**부터 한다. (별개 프로세스 vs 서브프로세스 구분 기준도 11단계에 있다.) 프로세스가 1개뿐이면 아래 추출 규칙대로 그대로 진행한다.

## 3. 문서에서 추출할 것 (as-is 프로세스)

문서를 읽으며 아래를 뽑아낸다. **있는 것만** 정확히, 없는 건 비워두고 나중에 컨설팅 질문으로 채운다.

- **프로세스명 / 목적**: 문서 제목·서두에서.
- **시작 트리거 / 종료 조건**: "~하면 시작", "~로 종료/완료".
- **단계(Activity)**: 각 단계는 *한 역할이 하는 하나의 작업*. 문서의 번호 목록·표의 행·"~한다" 문장에서 도출.
- **역할/담당자(roles)**: "담당", "승인권자", "신청자", 부서명 등.
- **분기(Gateway)**: "~인 경우 …, 아니면 …", "승인/반려", 금액·등급 기준 등 조건 분기.
- **되돌아감(loop)**: "반려 시 재작성", "보완 후 재제출".
- **입력/서류·산출물**: 각 단계에서 받는 서류·양식·데이터, 만들어내는 결과물. (5단계 폼·6단계 참조정보의 좋은 근거가 된다.)
- **서브프로세스 후보**: 문서에서 독립적으로 묶이는 절차 덩어리.

> 표(특히 xlsx)는 강력하다. "단계 | 담당 | 입력 | 조건 | 다음" 같은 열이 있으면 그대로 elements 로 매핑된다.

## 4. 추출 결과를 컨설팅 초안으로 제시

추출한 흐름을 [01-consulting.md](01-consulting.md) 의 초안 형식으로 사용자에게 **요약 제시**한다. 단, 지어낸 게 아니라 **문서에서 읽어낸 것**임을 분명히 한다:

```
업로드하신 [문서명] 을 읽고 현재 업무 흐름을 이렇게 정리했어요:

1. **신청** 단계 (역할: 직원) — 휴가 신청서 제출
2. **검토/결재** 단계 (역할: 팀장) — 신청 내용 확인
3. 분기: **승인** → 인사 등록 / **반려** → 신청자에게 통보 후 종료

문서에서 명확하지 않은 부분이 한 가지 있어요: (예) 반려되면 재신청이 가능한가요?
이 흐름에서 더하거나 바꿀 부분이 있으면 말씀해 주세요. 그대로 좋으면 프로세스 정의를 생성할게요.
```

원칙:
- **문서에 있는 내용은 다시 묻지 않는다** (중복 질문 금지). 문서로 못 채운 빈칸만 1~2개 질문.
- 문서 내용과 사용자 말이 **충돌**하면 사용자 말을 우선하되, 충돌 사실을 한 번 짚어 확인한다.
- 추출·합의된 흐름은 [01-consulting.md](01-consulting.md) 규칙대로 `.bpmn/01-consulting.md` 에 저장한다. 이때 헤더에 **출처 문서**를 적어둔다. 예: `출처 문서: 업무규정_v3.pdf (p.4–6)`.

이후는 동일하게 사용자 동의 → 2단계(JSON 생성)로 진행한다.

---

## 5. 주의

- 문서를 **그대로 베끼지 말 것.** 유효한 BPMN 흐름이 되도록 단계를 "한 역할의 한 작업"으로 쪼개고, 분기·종료를 분명히 한다(컨설팅 품질 규칙과 동일).
- 문서가 길어도 **프로세스와 무관한 내용**(연혁, 법적 고지 등)은 흐름에 넣지 않는다.
- 문서에서 시스템/도구 이름이 보여도 그것을 "사용 도구"로 묻거나 강제하지 않는다(컨설팅 금지 질문 규칙 유지). 우리가 그 도구를 만들어준다.
- 민감정보(주민번호·계좌 등 실제 값)가 문서에 있으면 흐름·양식의 *필드*로만 반영하고 실제 값은 산출물에 남기지 않는다.
