## 배경 조사

### 지금 ProcessGPT 의 판단 방식
| 위치 | 방식 |
|---|---|
| 엔진(polling 워크아이템 처리) | 온도 0 생성 → JSON 파서가 정규식·보정으로 정리 |
| 게이트웨이 분기 | 조건식을 코드로 평가(`conditionFunction`), 평가 못 하는 것만 LLM |
| deepagents · 클라이언트 라우터 | 함수 호출(tool calling)로 도구 선택 |

로그확률을 쓰는 코드는 없고, 판단의 확신도를 돌려주는 경로도 없다.

### 제공자별 logprobs (2026-10-23 직접 측정)
| 모델 | logprobs | 비고 |
|---|---|---|
| OpenAI `gpt-4o-mini`, `gpt-4.1-nano` | 지원 | 700~870ms |
| OpenAI 추론 모델 `o4-mini`, `gpt-5-mini` | 거부 | "You are not allowed to request logprobs from this model" |
| 사내 frentis(SGLang, Qwen3.6 35B) | 지원(생각 모드 끔) | 90~150ms. 생각 모드에서는 첫 토큰이 문장 |
| Anthropic | 미지원 | JSON 전략 대상 |

### JEV 와 open-alternative-jev
- JEV 는 TypeSafe AI 의 typed-decision 모델(유료 호스팅, 내부 비공개)이다.
- open-alternative-jev(`so1`, Apache-2.0)는 학습 없이 오픈 웨이트 모델에서 선택지 문자(A, B, C…)의 다음 토큰 로짓만 읽어 softmax 로 판단한다. 문장을 생성하지 않으므로 선택지 밖의 답이 없고, 순서 순열 평균(`permutations`)과 온도 보정을 제공한다. 로짓 접근이 필요해 채팅 API 만으로는 쓸 수 없다.

## 결정

### 1. 전략 패턴 + 판단 모델 최우선 + 에스컬레이션
- 세 전략은 같은 계약(상태·질문·선택지 → 선택·확률·전략·보정 여부)을 구현한다.
- 순서는 설정(`DECIDE_STRATEGIES`)이며 기본은 judge → logprob → json. 앞 전략이 설정되지 않았거나 응답하지 못하면 다음으로 넘어간다.
- 판단 모델은 빠르고 작지만 어려운 문항에서 틀릴 수 있다. 그래서 "판단 모델이 있으면 판단 모델 결과를 그대로 쓴다"가 아니라, **측정된 확신도가 기준(`DECIDE_ESCALATE_BELOW`)보다 낮으면 다음 전략으로 올린다.** 쉬운 판단은 판단 모델로 끝나고, 애매한 판단만 큰 모델 비용을 낸다.
- 측정 결과(로컬 Qwen3-4B 판단 모델): 단독 76% → 체인 95%, 판단 모델이 22건 중 16건을 확정하고 6건만 에스컬레이션.

### 2. logprob 전략의 가용성은 실행 중 판별
- 제공자·모델 목록을 하드코딩하지 않고, 첫 호출에서 로그확률이 오는지, 선택지 문자가 첫 토큰 확률의 절반 이상을 차지하는지 보고 판별해 (엔드포인트, 모델) 단위로 기억한다.
- 문장이 먼저 나오는 생각 모드 모델은 `chat_template_kwargs.enable_thinking=false` 로 한 번 재시도한다(SGLang/vLLM 이 받는 형식). 추론 모델의 파라미터 차이(`max_completion_tokens`, 기본 온도만 허용)는 오류 메시지를 보고 맞춘다.

### 3. JSON 전략의 확신도는 "자기 보고"로 표시
- 모델이 적은 숫자는 측정값이 아니므로 `calibrated: false` 로 표시하고, 라우팅 기준을 더 높게 적용한다(기본 0.55 → 0.70).

### 4. 라우터는 에이전트 앞의 별도 서비스
- SDK(processgpt_agent_sdk)는 외부 패키지라 채팅 진입점을 직접 고치지 않는다. 대신 라우터가 SDK 채팅 계약 그대로의 요청을 만들어 에이전트로 전달한다. 에이전트는 무엇이 바뀌었는지 모른다.
- 게이트웨이에서 에이전트 경로만 라우터로 돌리면 앞단에 놓인다. 그래서 채팅 외 경로(재접속, 스킬, 파일)도 그대로 전달한다.
- 기존 대화방(대화가 고정된 방)의 대화를 몰래 바꾸면 안 되므로 라우팅은 요청별 선택이며 기본은 끔이다.

### 5. 확신이 없으면 머문다
- 엉뚱한 대화로 옮기는 것이 같은 대화에 머무는 것보다 해롭다. 기준 미만이면 `stay`.

## 트레이드오프와 남은 일
- 참조 판단 서버는 GPU(또는 Apple MPS)가 필요하다. 4B 모델은 "새 주제"를 잘 고르지 못한다 — 더 큰 판단 모델(8B 이상, vLLM 백엔드)이나 TypeSafe JEV 를 같은 계약 어댑터로 붙이면 판단 모델 단독 비중을 높일 수 있다.
- 진행 중인 실행에 끼워 넣기(steering)는 이번 범위가 아니다. 라우팅된 대화에 실행 중인 턴이 있으면 에이전트의 기존 동작을 따른다.
- 맥락 제목은 첫 메시지 앞부분이다. 요약 모델로 짧은 제목을 만드는 것은 후속.

## 다른 판단 지점에 대한 적용성
- **엔진의 LLM 분기 판단**: 조건식으로 평가하지 못한 분기 선택을 `POST /decide` 로 바꾸면 확률이 남아 판단 이력(decision journal)에 확신도를 기록할 수 있다.
- **브라우저 에이전트(browser use)**: 매 턴 큰 모델에 화면을 보내는 루프에서 "로그인 벽인가 / 목표를 이미 달성했나 / 지금 페이지가 목표와 관련 있나 / 다음 행동 유형(클릭·입력·스크롤·종료)" 같은 짧은 판단을 판단 모델로 먼저 걸러, 확실한 경우 큰 모델 호출을 건너뛸 수 있다. 요소 선택(수십 개 후보)은 후보 압축 후 26개 이하로 줄여야 한다. 별도 측정이 필요하다.
