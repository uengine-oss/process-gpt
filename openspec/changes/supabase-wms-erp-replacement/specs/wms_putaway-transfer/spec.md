# WMS 적치·내부 이동 명세

## ADDED Requirements

### Requirement: 규칙 기반 적치 위치 추천 (WMS-PUT-001)
시스템은 창고, 상품군, 온도대, 위험물, lot, 기존 재고, 위치 용량과 우선순위 규칙으로 목적 위치를 SHALL 추천한다.

#### Scenario: 동일 상품 근접 적치
- **GIVEN** 호환 가능한 여러 위치 중 동일 상품·lot이 있는 위치에 충분한 용량이 있다
- **WHEN** 시스템이 적치 위치를 계산한다
- **THEN** 시스템은 규칙 우선순위에 따라 해당 위치를 추천한다
- **AND** 적용 규칙과 남은 용량을 표시한다

#### Scenario: 적합한 위치 없음
- **GIVEN** 모든 후보 위치가 용량 또는 호환성 조건을 위반한다
- **WHEN** 적치 작업을 만들려 한다
- **THEN** 시스템은 임의 위치를 선택하지 않고 위치 부족 예외를 생성한다

### Requirement: 적치 작업 생성 (WMS-PUT-002)
시스템은 합격 입고 수량을 handling unit 또는 상품·lot 단위의 출발, 목적, 수량이 있는 작업으로 SHALL 생성한다.

#### Scenario: 부분 합격 적치
- **GIVEN** receipt 100 EA 중 90 EA만 합격했다
- **WHEN** 적치 작업을 생성한다
- **THEN** 시스템은 합격 90 EA만 작업 대상으로 설정한다
- **AND** 불합격 10 EA는 격리 위치에 유지한다

### Requirement: 스캔 검증 적치 (WMS-PUT-003)
시스템은 출발 위치, handling unit/상품, 필요 시 lot/serial, 목적 위치의 순차 스캔을 검증하여 작업을 SHALL 완료한다.

#### Scenario: 잘못된 목적 위치 스캔
- **GIVEN** 작업의 추천 또는 허용 목적 위치가 정해져 있다
- **WHEN** 작업자가 호환되지 않는 다른 위치를 스캔한다
- **THEN** 시스템은 이동을 기록하지 않고 올바른 위치 또는 예외 절차를 안내한다

### Requirement: 원자적 적치 완료 (WMS-PUT-004)
시스템은 작업 완료와 재고 위치·상태 전환을 하나의 트랜잭션으로 SHALL 처리한다.

#### Scenario: 최종 선반 적치
- **GIVEN** 합격품이 PUTAWAY_PENDING 상태로 입고 위치에 있다
- **WHEN** 작업자가 최종 보관 위치 스캔을 완료한다
- **THEN** 시스템은 입고 위치 차감과 보관 위치 AVAILABLE 증가를 같은 movement에 기록한다
- **AND** 작업을 COMPLETED로 전환하고 ProcessGPT에 적치 완료 이벤트를 발행한다

### Requirement: 내부 이동 통제 (WMS-PUT-005)
시스템은 보관·피킹·보충 위치 사이의 내부 이동에도 동일한 용량, 호환성, 예약과 추적 규칙을 SHALL 적용한다.

#### Scenario: 예약 재고 이동
- **GIVEN** 이동 대상 일부가 출고 주문에 예약되어 있다
- **WHEN** 일반 내부 이동이 예약 수량을 포함하려 한다
- **THEN** 시스템은 예약을 보존할 수 있는 승인된 이동이 아니면 요청을 거부한다
