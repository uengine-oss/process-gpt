# WMS 기준정보 명세

## ADDED Requirements

### Requirement: 창고 위치 계층 관리 (WMS-MD-001)
시스템은 테넌트와 회사별로 창고, 존, 로케이션, 도크의 계층과 위치 유형, 활성 상태를 SHALL 관리한다.

#### Scenario: 창고 위치 생성
- **GIVEN** 기준정보 관리자가 테넌트와 회사 범위에 접근할 수 있다
- **WHEN** 관리자가 창고 아래에 입하, 품질, 보관, 피킹, 포장, 출하 또는 폐기 유형의 위치를 생성한다
- **THEN** 시스템은 유일한 위치 코드와 부모 경로를 검증하고 위치를 저장한다
- **AND** 다른 테넌트의 위치는 부모로 선택할 수 없다

#### Scenario: 사용 중 위치 비활성화
- **GIVEN** 위치에 재고 또는 열린 작업이 있다
- **WHEN** 관리자가 위치를 비활성화한다
- **THEN** 시스템은 신규 이동 목적지 사용을 차단한다
- **AND** 기존 이력과 잔량은 보존하고 정리해야 할 재고·작업을 표시한다

### Requirement: 위치 용량과 호환성 (WMS-MD-002)
시스템은 위치의 중량·부피·팔레트 용량과 온도대, 위험물, 상품군 호환 규칙을 SHALL 관리한다.

#### Scenario: 허용되지 않는 상품 배치
- **GIVEN** 목적 위치가 상품의 온도대 또는 위험물 등급과 호환되지 않는다
- **WHEN** 사용자가 해당 위치로 적치 또는 이동을 요청한다
- **THEN** 시스템은 명령을 거부하고 위반한 규칙과 가능한 대체 위치를 반환한다

### Requirement: 상품·단위·포장 기준정보 (WMS-MD-003)
시스템은 SKU, 명칭, 기본 UOM, UOM 환산, 포장단위, 중량·부피, 유통기한, lot/serial 추적 정책을 SHALL 관리한다.

#### Scenario: 포장단위 수량 환산
- **GIVEN** 상품의 1 BOX가 12 EA로 유효기간과 함께 정의되어 있다
- **WHEN** 사용자가 3 BOX를 입고한다
- **THEN** 시스템은 거래 단위와 함께 기본 단위 36 EA를 저장한다
- **AND** 이후 원장 합계는 기본 단위로 일관되게 계산한다

#### Scenario: 추적 필수 상품의 식별자 누락
- **GIVEN** 상품이 lot 또는 serial 필수로 설정되어 있다
- **WHEN** 사용자가 식별자 없이 입고·이동·출고를 확정한다
- **THEN** 시스템은 확정을 거부하고 필요한 식별자 유형을 반환한다

### Requirement: 상품 바코드 식별 (WMS-MD-004)
시스템은 하나의 상품에 GTIN, 내부 코드와 포장단위별 복수 바코드를 SHALL 연결한다.

#### Scenario: 바코드 중복 등록
- **GIVEN** 동일 테넌트에 이미 사용 중인 바코드가 있다
- **WHEN** 관리자가 다른 상품 또는 포장에 같은 바코드를 등록한다
- **THEN** 시스템은 모호한 식별을 방지하기 위해 등록을 거부한다

### Requirement: 공급사와 구매 조건 (WMS-MD-005)
시스템은 공급사, 공급사별 상품 코드, 최소 주문량, 주문 배수, 가격, 통화, 리드타임과 납품 조건을 SHALL 관리한다.

#### Scenario: 재보충용 공급 조건 선택
- **GIVEN** 한 상품에 여러 공급사의 유효한 공급 조건이 있다
- **WHEN** 시스템이 구매 제안을 계산한다
- **THEN** 시스템은 우선순위와 유효기간을 적용해 조건을 선택한다
- **AND** 선택 근거와 대체 공급 조건을 제안에 기록한다

### Requirement: 기준정보 이력 보존 (WMS-MD-006)
시스템은 거래에 사용된 기준정보를 삭제하지 않고 비활성화하며 변경 이력을 SHALL 보존한다.

#### Scenario: 공급사 비활성화
- **GIVEN** 공급사에 과거 PO가 존재한다
- **WHEN** 관리자가 공급사를 비활성화한다
- **THEN** 신규 RFQ에는 공급사를 선택할 수 없다
- **AND** 과거 PO와 감사 조회에는 당시 공급사 정보가 유지된다
