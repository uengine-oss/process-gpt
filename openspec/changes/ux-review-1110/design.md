## 결정

결정한 사람과 이유는 `docs/decisions/2026-11.md`에 있다. 여기에는 구현에서 정한 세부만 적는다.

| 무엇 | 정한 것 | 이유 |
|---|---|---|
| 「내 업무」로 세는 상태 | `IN_PROGRESS` · `SUBMITTED` · `PENDING` | 「나의 업무」 화면의 진행 중 · 보류/반송 칸과 같다. `TODO`는 엔진이 앞 단계를 위해 미리 만들어 두는 예정 업무다(인스턴스 칸반의 「예정업무」) |
| 담당자 맞추기 | `user_id`를 쉼표로 나눠 정확히 같은 값 | `LIKE '%uid%'`는 후보만 고른다. 다른 id의 일부가 겹쳐도 세지 않는다 |
| 묶는 단위 | 최상위 인스턴스 | 사이드바는 최상위 인스턴스만 보인다 |
| 휴대폰 | 할 일 줄 유지 | 휴대폰에서는 그것이 주 화면이다(스모크 시험 `simple-ui-mobile-work`도 그 길을 쓴다) |
| 칩 다시 세기 | 인스턴스 목록을 다시 읽을 때와 `todolist-updated` 때 | 업무 행 실시간 구독을 더하지 않는다(사이드바마다 구독이 하나 더 생긴다) |
| 에이전트 이름 | 이름 + 괄호 안 엔진 | 코덱스도 딥 에이전트다. 같은 이름 아래 엔진으로 구별한다 |

## 딥 에이전트로 만들 때 생기던 문제

설치본(VM)에서 3장 프롬프트를 딥 에이전트로 여러 번 돌려 찾았다(`specs/deepagents_process-generation-chat/e2e/`).

1. **보류**: 운영 deepagents(master)에는 튜토리얼 촬영 중 고친 PR 10개가 없다. 정의를 안내받지 않은 폴더에 쓰거나, 잘린 JSON을 쓰거나, 보류 사유를 다음 차례 모델이 모르면 「결과 전달을 보류했어요」로 끝났다. 10개를 합친 판에서는 3번 모두 생성으로 끝났다.
2. **답 앞의 영수증**: `graph.astream(..., subgraphs=True)`는 `task` 도구로 부른 서브에이전트의 토큰도 흘린다. 스킬 작성 서브에이전트가 돌려주는 「created: /workspace/…/SKILL.md 영업 제안서 작성 자동화」가 최종 답 앞에 붙어 저장됐다.
   - 고침: 네임스페이스가 `tools:`인 글은 스트리밍 · 저장하지 않는다. 서브에이전트의 결과는 도구 결과로 메인 에이전트에게 간다.
3. **고르지 않은 후보를 만듦**: 후보 질문에 아무것도 고르지 않으면 프런트는 「없음」만 보낸다. 모델이 그 뒤에도 후보 스킬을 만드는 회차가 있었다(3번 중 2번).
   - 고침: 후보 질문의 답이 비었거나 「없음」류이면 도구 결과에 '하나도 고르지 않았다 · 스킬 · 에이전트 · DMN을 만들지 않는다 · 폼과 참조정보는 만든다'를 적어 돌려준다.
4. **같은 질문이 두 번**: 질문은 스트리밍 중 도구 인자로 한 번, 서버가 저장한 행이 실시간으로 다시 올 때 본문에서 한 번 그려진다. 둘째 패널은 「제출함」 표시가 없어 이미 승인한 질문이 다시 열려 보였다. 다시 누르면 「승인」이 두 번 가고, 둘째 「승인」이 다음 질문(후보)의 답이 되어 빈 후보 패널이 남았다.
   - 고침: 실시간 행이 같은 메시지를 갱신할 때 이미 제출한 패널을 지키고, 뒤에 사람의 말이 있는 deepagent 패널은 「제출함」으로 닫는다.

남은 것: 초안 질문 문장이 패널 머리와 본문에 세 번 되풀이된다(스킬 문서의 질문 형식). 이번에는 고치지 않았다.
