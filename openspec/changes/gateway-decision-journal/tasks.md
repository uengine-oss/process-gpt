## 1. 현재 동작 고정 (제품 코드 변경 없음)

- [x] 1.1 분기 판단 시나리오별 회귀 테스트를 먼저 작성해 현재 선택 결과를 고정한다. 대상: 배타 분기 단일 참, 참 다수(우선순위), 참 없음(기본 흐름), 참도 기본 흐름도 없음, 병렬 분기, 병합 대기. 완료 기준: 이력 기능을 붙이기 전후로 선택 결과가 동일함을 이 테스트로 확인할 수 있다.
- [x] 1.2 조건식 평가 실패, 자연어 조건 판정, 조건 없는 단일 경로 각각에 대한 판정 경로를 테스트로 고정한다. 검증 대상: `판단 방식과 근거 기록`의 판정 방식 구분 시나리오.
- [x] 1.3 현재 판정 로직이 "평가 없음·평가 실패"를 거짓처럼 취급하는 지점을 테스트로 명시한다. 검증 대상: `판단 방식과 근거 기록`의 조건식 평가 실패 후 대체 시나리오. 완료 기준: 참 판정과 판정 불가가 구분되어야 할 지점이 테스트에 드러난다.

## 2. 이벤트 계약 정의

- [x] 2.1 판단 이력 이벤트와 모델 원문 이벤트의 본문 형태를 계약 문서로 확정한다. 검증 대상: `분기 판단 이력 기록`, `판단 방식과 근거 기록`. 완료 기준: 필수 필드와 선택 필드, 판정 결과 값(참·거짓·판정 불가), 결과 값(진행·대기·진행 불가)이 확정된다.
- [x] 2.2 이벤트 종류 열거형 확장 마이그레이션을 작성한다. 완료 기준: 기존 데이터 손실 없이 새 값이 추가되고, 마이그레이션 재실행이 안전하다.
- [x] 2.3 입력 스냅샷 크기 상한과 잘림 표시 방식을 확정한다. 검증 대상: `판단 입력 스냅샷 기록`의 크기 상한 초과 시나리오.
- [x] 2.4 판단 이력과 모델 원문의 상호 참조 방식을 확정한다. 검증 대상: `모델 판정 원문 보존`의 원문 만료 시나리오.
- [ ] 2.5 판단 이력 본문과 모델 원문 각각의 보존 기간을 확정하고 정리 작업을 붙인다. **미완**: 현재는 이벤트가 무기한 쌓인다.

## 3. 기록 구현

- [x] 3.1 시퀀스 조건 평가 단계에서 판정 방식·조건식 원문·판정 결과·근거를 유실 없이 수집한다. 검증 대상: `판단 방식과 근거 기록` 전 시나리오. 완료 기준: 참·거짓·판정 불가가 서로 구분되어 수집된다.
- [x] 3.2 분기 선택 단계에서 판단 주체 노드, 선택·미선택 시퀀스, 결과 구분을 확정해 이력 한 건을 구성한다. 검증 대상: `분기 판단 이력 기록`, `진행 불가와 대기 상태 구분 기록`.
- [x] 3.3 병합 대기 판정 결과를 대기 이력으로 기록하고 기다리는 대상을 식별 가능하게 한다. 검증 대상: `진행 불가와 대기 상태 구분 기록`의 병합 대기 시나리오.
- [x] 3.4 재실행 회차와 실행 범위를 이력에 포함해 회차별로 누적되게 한다. 검증 대상: `재실행 회차별 이력 누적` 전 시나리오.
- [x] 3.5 자연어 조건 판정의 프롬프트·응답 원문을 별도 이력으로 남기고 상호 참조를 건다. 검증 대상: `모델 판정 원문 보존`. 완료 기준: 조건식만으로 판정된 분기에는 원문 이력이 생성되지 않는다.
- [x] 3.6 판단 입력 스냅샷을 수집하되 분기 참조 데이터를 우선한다. 검증 대상: `판단 입력 스냅샷 기록`.
- [x] 3.7 기록을 프로세스 진행 경로와 분리하고, 기록 실패를 예외 전파 없이 관측 신호로만 남긴다. 검증 대상: `이력 기록 실패 격리` 전 시나리오. 완료 기준: 이벤트 저장소를 강제로 실패시켜도 다음 활동 워크아이템이 정상 생성된다.

## 4. 조회

- [x] 4.1 인스턴스 단위·워크아이템 단위 판단 이력 조회를 제공한다. 검증 대상: `판단 이력 조회`.
- [x] 4.2 인스턴스 이력으로부터 지나간 시퀀스 집합을 확정하는 조회를 제공한다. 완료 기준: 선택되지 않은 갈래의 시퀀스가 결과에 포함되지 않는다.
- [x] 4.3 테넌트 범위를 벗어난 이력이 조회되지 않음을 검증한다. 검증 대상: `판단 입력 스냅샷 기록`의 테넌트 격리 시나리오. **주의**: 현재는 조회 계층 필터링이며 DB 레벨 RLS 는 4.6 으로 남긴다.
- [x] 4.4 이력이 없는 과거 인스턴스가 빈 결과로 응답함을 검증한다. 검증 대상: `판단 이력 조회`의 과거 인스턴스 시나리오.
- [ ] 4.5 실행 중 새 판단이 기록될 때 관찰 중인 클라이언트가 재조회 없이 인지함을 검증한다. 검증 대상: `판단 이력 조회`의 실시간 반영 시나리오. **미완**: `events` 는 이미 realtime publication 에 포함되어 있으나 구독 경로를 실측하지 않았다.
- [ ] 4.6 `events` 테이블에 테넌트 백필 후 DB 레벨 RLS 를 적용한다. **미완**: 과거 행의 `tenant_id` 가 NULL 이고 다른 서비스가 이 테이블에 쓰고 있어 지금 켜면 기존 조회가 끊긴다.

## 5. 회귀 확인

- [x] 5.1 1장의 회귀 테스트를 다시 실행해 분기 선택 결과가 이력 기능 도입 전과 동일함을 확인한다. 완료 기준: 선택 결과 차이가 0건이다.
- [ ] 5.2 판단 이력 기록으로 인한 워크아이템 처리 지연을 측정한다. **미완**: 기록을 임계 경로 밖으로 뺐으므로 구조적으로는 지연이 없지만, 실부하 측정은 하지 않았다.
- [x] 5.3 진행 불가 이력이 실제로 관측되는지 확인한다. 완료 기준: 참인 갈래도 기본 흐름도 없는 분기를 처리하면 진행 불가 이력이 남는다.
