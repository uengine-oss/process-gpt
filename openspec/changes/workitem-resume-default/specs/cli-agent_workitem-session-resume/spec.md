## ADDED Requirements

### Requirement: RE-1 실행 시작 직후 세션을 기록하고 크래시 재점유 때 그 세션으로 이어 간다
cli-agent는 CLI가 세션 ID를 알리는 즉시, 실행이 끝나기 전에 작업 공간에 그 세션 ID를 기록해야 한다(SHALL). 재개 사유가 `reclaim`이고 기록된 세션이 있으면, 원래 지시를 다시 넣지 않고 그 세션을 재개하며 "중단된 지점부터, 완료한 단계는 다시 하지 말 것" 지시를 넣어야 한다(SHALL). 이미 실행된 명령은 다시 실행되지 않아야 한다(MUST).

#### Scenario: RE-1.3 단계 사이에서 죽은 뒤 재점유
- **WHEN** CLI 에이전트가 1단계를 끝내고 2단계 명령 중에 죽고, 같은 작업 공간에서 `reclaim`으로 다시 집힌다
- **THEN** 실행 시작 직후 기록된 세션이 재개되고 이어서 지시가 들어가며, 1단계 명령은 다시 실행되지 않는다

#### Scenario: RE-1.4 세션 ID는 실행 시작 직후 기록된다
- **WHEN** CLI 실행이 첫 이벤트로 세션 ID를 알린다
- **THEN** 실행이 끝나기 전에 작업 공간에 그 세션 ID가 기록되어 있다

#### Scenario: RE-1.5 기록된 세션이 없는 재점유
- **WHEN** `reclaim`으로 집혔지만 기록된 세션이 없거나 작업 공간이 정리됐다
- **THEN** 원래 지시로 새 세션을 시작한다

### Requirement: RE-2.0 권한 때문에 막히면 실패하지 않고 사람에게 묻는다
CLI 에이전트가 권한 승인이 필요한 동작을 거부당했고, 그 실행이 요구된 결과(폼)를 채우지 못했으면 cli-agent 는 작업을 실패로 끝내지 않고 사람에게 묻고 멈춰야 한다(SHALL). 이때 작업은 `HUMAN_ASKED` 가 되고, 화면이 질문 카드를 그릴 수 있도록 `human_asked` 이벤트에 질문(`question`)과 답 형식(`type`)을 남겨야 한다(MUST). 거부를 우회해 요구된 결과를 냈으면 이전처럼 결과를 저장하고 거부 사실만 알린다. CLI 가 거부를 "requires approval" 같은 도구 오류로 알려도 권한 거부로 본다.

#### Scenario: RE-2.0.1 승인이 필요한 명령이 거부되고 결과가 비었다
- **WHEN** workspace_write 권한으로 실행한 CLI 가 네트워크 명령을 "This command requires approval" 로 거부당하고, 결과 폼을 채우지 못한 채 끝난다
- **THEN** 작업은 `FAILED` 가 아니라 `HUMAN_ASKED` 가 되고, 화면의 작업 화면에 그 거부 문구를 담은 질문 카드가 보인다

#### Scenario: RE-2.0.2 거부를 우회해 결과를 냈다
- **WHEN** 거부가 있었지만 에이전트가 다른 방법으로 요구된 결과를 채웠다
- **THEN** 결과는 저장되고, 거부 사실은 알림으로만 남는다

### Requirement: RE-2 사람 답변이면 멈춘 세션으로 이어 가고 답 원문을 넣는다
재개 사유가 `human_answer`이면 cli-agent는 사람에게 묻고 멈춘 세션을 재개해야 하며(SHALL), 프롬프트에 `answer_raw` 원문을 그대로 넣어야 한다(MUST). 요약본만 넣어서는 안 된다(MUST NOT). 답을 쓴 뒤에는 멈춤 기록을 지워, 이후의 반려를 사람 답변으로 오인하지 않아야 한다(MUST).

#### Scenario: RE-2.1 권한이 필요해 멈춘 뒤 답변
- **WHEN** 세션 `S`에서 멈춘(`HUMAN_ASKED`) 작업에 사람이 "허용합니다. 계속 진행하세요"로 답해 `human_answer`로 다시 집힌다
- **THEN** 세션 `S`가 재개되고, 프롬프트에 그 답 원문과 이어서 지시가 들어가며 요약 피드백은 들어가지 않는다

#### Scenario: RE-2.2 구분 표시 없는 답이지만 멈춘 기록이 남아 있음
- **WHEN** 작업 공간에 멈춘 기록이 남아 있고, `kind` 없는(구버전 화면) 답이 `revision`으로 넘어온다
- **THEN** 그 답을 사람 답변으로 보고 RE-2.1과 같이 멈춘 세션을 재개한다

### Requirement: RE-3 재개 정보가 없으면 이전 동작을 유지한다
실행 문맥에 재개 정보가 없거나 사유가 `fresh`·`revision`(멈춘 기록 없음)이면, cli-agent는 이번 변경 이전과 같은 프롬프트와 세션 규칙으로 실행해야 한다(SHALL).

#### Scenario: RE-3.1 신규 실행과 반려
- **WHEN** `resume`이 없거나 `fresh`인 작업, 또는 이전 결과에 세션이 기록된 `revision` 작업이 집힌다
- **THEN** 신규는 원래 지시로 새 세션을, 반려는 이전 결과에 기록된 세션을 쓴다(이번 변경 이전과 같다)
