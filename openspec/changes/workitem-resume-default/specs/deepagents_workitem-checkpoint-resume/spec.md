## ADDED Requirements

### Requirement: RE-1 크래시 재점유 뒤 마지막 체크포인트부터 이어 간다
재개 사유가 `reclaim`이고 그 작업의 그래프 체크포인트에 더 진행할 단계가 남아 있으면, deepagents는 원래 지시를 새 입력으로 다시 넣지 않고 마지막 체크포인트부터 이어서 실행해야 한다(SHALL). 이미 결과가 기록된 도구 호출은 다시 실행하지 않아야 한다(MUST). 중단 시점에 진행 중이던 도구는 다시 실행될 수 있다(at-least-once). 사람 답을 기다리는 질문이 남아 있으면 그 답으로 잇는 것이 우선한다(`deepagents_workitem-human-input`).

#### Scenario: RE-1.1 도구 실행 중 프로세스가 죽은 뒤 재점유
- **WHEN** 외부 조회 도구가 끝나고 보고서 생성 도구가 도는 중에 프로세스가 죽고, 다른 프로세스가 `reclaim`으로 같은 작업을 집는다
- **THEN** 재개 실행에서 외부 조회 도구는 0회 호출되고, 모델 호출 총수는 중단되지 않았을 때보다 늘지 않으며, 대화에 원래 지시가 두 번 들어가지 않는다

#### Scenario: RE-1.2 그래프가 이미 끝난 체크포인트
- **WHEN** `reclaim`으로 집혔지만 체크포인트의 그래프가 더 진행할 단계가 없다(결과 저장 직전에 죽음)
- **THEN** 이전처럼 지시를 새로 넣어 실행한다

### Requirement: RE-3 재개 정보가 없으면 이전 동작을 유지한다
실행 문맥에 재개 정보가 없거나 사유가 `fresh`·`revision`·`human_answer`이면, deepagents는 이번 변경 이전과 같은 입력으로 실행해야 한다(SHALL).

#### Scenario: RE-3.1 구버전 SDK
- **WHEN** 실행 문맥에 `resume`이 없는 상태로 체크포인트가 남은 작업이 다시 집힌다
- **THEN** 재개 입력은 이번 변경 이전과 같다(지시를 새 메시지로 덧붙인다)

### Requirement: RE-4 지속 체크포인트 저장소 실패를 숨기지 않는다
지속 저장소 접속 정보(`DB_HOST`, `DB_NAME` 등 `DB_*`)가 설정됐는데 저장소 초기화에 실패하면, deepagents는 프로세스 메모리 저장으로 대체해 계속 실행해서는 안 된다(MUST NOT). 기동 시점이면 기동을 실패시키고(SHALL), 실행 시점이면 해당 작업을 오류로 끝내 화면에 알린다(SHALL). 접속 정보가 아예 없을 때(로컬 개발)만 메모리 저장을 쓴다.

#### Scenario: RE-4.1 기동 시 저장소 접속 실패
- **WHEN** `DB_*`가 설정됐지만 Postgres에 접속할 수 없는 상태에서 서비스를 기동한다
- **THEN** 서비스는 오류 로그를 남기고 0이 아닌 종료 코드로 끝난다

#### Scenario: RE-4.2 실행 중 저장소 초기화 실패
- **WHEN** `DB_*`가 설정됐는데 작업 실행 시점에 체크포인트 저장소를 열 수 없다
- **THEN** 작업은 메모리 저장으로 진행되지 않고 오류 이벤트와 함께 `FAILED`로 끝나며, 일정 시간이 지난 다음 작업에서 다시 초기화를 시도한다

#### Scenario: RE-4.3 접속 정보 없음
- **WHEN** `DB_*`가 설정되지 않았다
- **THEN** 서비스는 메모리 체크포인터로 기동·실행하고 경고를 남긴다
