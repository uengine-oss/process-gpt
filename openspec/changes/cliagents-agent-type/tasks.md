## 1. 서브모듈 연결과 기반 정리

- [x] 1.1 `services/cliagents` 서브모듈로 https://github.com/uengine-oss/cliagents 를 추가하고, 클론/초기화 절차를 설치 문서에 반영한다. 완료 기준: 신규 클론에서 서브모듈 초기화만으로 라이브러리 테스트가 통과한다.
- [x] 1.2 라이브러리와 ProcessGPT 서비스를 분리한다. 서비스는 별도 저장소(uengine-oss/process-gpt-cli-agent)로 두고 `services/cli-agent` 서브모듈로 등록한다. 완료 기준: 서비스 의존성이 없는 환경에서 라이브러리 테스트가 그대로 통과한다.
- [x] 1.3 라이브러리 무의존성 회귀를 막는 검증을 CI 에 추가한다. 완료 기준: 라이브러리 코드가 표준 라이브러리 밖 모듈을 임포트하면 검증이 실패한다.

## 2. headless 실행 표면 (라이브러리)

- [x] 2.1 실행 표면 계약(실행 argv 구성, 이벤트 정규화, 세션 식별자 추출·재개)을 provider 인터페이스에 추가한다. 검증 대상: `cliagents_workitem-task-execution` 의 실행/취소/타임아웃 시나리오 전제 조건.
- [x] 2.2 Claude Code provider 의 비대화형 실행과 구조화 스트림 파싱을 구현한다. 완료 기준: 프롬프트 한 건 실행이 텍스트 증분·도구 시작/종료·최종 결과 이벤트로 정규화된다.
- [x] 2.3 Codex provider 의 비대화형 실행과 JSON 출력 파싱을 구현한다. 완료 기준: 동일한 프롬프트가 Claude Code 와 동일한 정규화 이벤트 형태로 관측된다.
- [x] 2.4 모델·권한 수준·세션 재개 옵션을 CLI 별 플래그로 번역한다. 검증 대상: `cliagents_cli-selection-availability` 의 권한/모델 시나리오.
- [x] 2.5 알 수 없는 이벤트를 폐기하지 않고 통과시키는 동작을 구현한다. 검증 대상: `cliagents_chat-streaming-session` 의 "알 수 없는 CLI 이벤트 처리" 시나리오.
- [x] 2.6 실행 표면 계약 테스트를 추가한다(CLI 미설치 환경에서는 건너뛰기). 완료 기준: 두 provider 가 같은 계약 테스트를 통과한다.

## 3. 서비스 골격과 업무 실행

- [x] 3.1 오케스트레이션 `cliagents` 를 폴링하는 서비스 기동 경로와 헬스 확인 경로를 만든다. 검증 대상: `cliagents_workitem-task-execution` 의 폴링 시나리오.
- [x] 3.2 다른 오케스트레이션 워크아이템을 점유하지 않음을 검증한다. 검증 대상: 같은 스펙의 "다른 오케스트레이션 업무는 건드리지 않는다".
- [x] 3.3 업무 컨텍스트(담당자, 업무 설명, 입력 데이터, 출력 형식)를 실행 프롬프트로 구성한다. 검증 대상: 출력 형식 계약 요구사항.
- [x] 3.4 초안/완료 모드별 결과 저장과 담당자 통지를 구현한다. 검증 대상: 실행 결과 저장 모드 시나리오 2건.
- [x] 3.5 출력 형식 불일치, 실행 오류, 타임아웃의 실패 보고를 구현한다. 검증 대상: 실패/타임아웃 시나리오.
- [x] 3.6 실행 취소와 프로세스 정리를 구현한다. 완료 기준: 취소 후 남은 CLI 프로세스가 없고 업무가 재실행 가능한 상태가 된다.
- [x] 3.7 동시 실행 상한 설정과 상한 도달 시 미점유 동작을 구현한다. 검증 대상: 동시 실행 상한 시나리오.
