## ADDED Requirements

### Requirement: 실행 단위 워크스페이스 격리
시스템은 각 업무/대화 실행에 대해 고유한 작업 디렉터리를 제공하고, 다른 실행의 작업 디렉터리에 접근할 수 없게 해야 한다(SHALL NOT). 기본 권한에서 에이전트의 파일 쓰기는 자신의 작업 디렉터리 안으로 제한되어야 한다(SHALL).

#### Scenario: 실행별 작업 공간 분리
- **WHEN** 서로 다른 두 업무가 동시에 실행되면
- **THEN** 각 실행은 자신의 작업 디렉터리만 보고, 상대의 파일을 읽거나 수정할 수 없다

#### Scenario: 워크스페이스 밖 쓰기 시도
- **WHEN** 기본 권한 설정에서 에이전트가 작업 디렉터리 밖에 파일을 쓰려 하면
- **THEN** 쓰기가 허용되지 않고, 시도 사실이 실행 기록에 남는다

### Requirement: 파일 생성·수정의 실시간 통지
시스템은 실행 중 작업 디렉터리에서 생성되거나 수정된 파일을 실시간으로 클라이언트에 알려야 한다(SHALL). 통지에는 파일 경로, 변경 종류, 미리보기 가능한 내용이 포함되어야 하며, 과도하게 큰 파일은 잘라서 전달해야 한다(SHALL).

#### Scenario: 산출물 생성 시 즉시 표시
- **WHEN** 에이전트가 실행 중 문서 파일을 생성하면
- **THEN** 사용자 화면에 해당 파일이 생성되었음이 실행 도중 표시된다

#### Scenario: 대용량 파일 미리보기
- **WHEN** 생성된 파일이 미리보기 제한 크기를 초과하면
- **THEN** 내용은 제한 크기까지만 전달되고 잘렸다는 사실이 함께 표시된다

### Requirement: 산출물 다운로드
시스템은 실행이 만든 파일을 다운로드할 수 있는 경로를 제공해야 한다(SHALL). 다른 실행이나 다른 테넌트의 파일 요청은 거부해야 한다(SHALL NOT serve).

#### Scenario: 생성된 파일 내려받기
- **WHEN** 사용자가 실행이 만든 파일의 다운로드를 요청하면
- **THEN** 해당 파일이 원본 파일명과 적절한 형식으로 전달된다

#### Scenario: 권한 없는 파일 요청
- **WHEN** 사용자가 자신의 실행이 아닌 파일 경로를 요청하면
- **THEN** 요청이 거부되고 파일 내용이 전달되지 않는다

### Requirement: 워크스페이스 보존과 정리
시스템은 재개와 산출물 확인을 위해 워크스페이스를 실행 종료 후에도 설정된 기간 동안 보존해야 하며(SHALL), 기간이 지나면 정리해야 한다(SHALL). 보존 중인 워크스페이스는 서비스 재시작 후에도 남아 있어야 한다(SHALL).

#### Scenario: 서비스 재시작 후 산출물 유지
- **WHEN** 실행 종료 후 서비스가 재시작되면
- **THEN** 보존 기간 내의 산출물은 여전히 조회·다운로드 가능하다

#### Scenario: 보존 기간 경과
- **WHEN** 설정된 보존 기간이 지나면
- **THEN** 해당 워크스페이스가 정리되고, 이후 재개 시도는 이어가기 불가로 처리된다
