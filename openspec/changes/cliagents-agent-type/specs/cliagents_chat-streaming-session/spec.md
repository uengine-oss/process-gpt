## ADDED Requirements

### Requirement: 채팅 실행의 진행 이벤트 스트리밍
시스템은 CLI 에이전트와의 대화 실행에 대해 진행 상황을 SSE 로 실시간 전달해야 한다(SHALL). 이벤트는 어시스턴트 텍스트 증분, 도구 시작(`tool_start`), 도구 종료(`tool_end`), 계획 갱신, 최종 결과, 오류를 구분할 수 있어야 한다(SHALL).

#### Scenario: 대화 요청에 대한 실시간 스트리밍
- **WHEN** 클라이언트가 `/chat/stream` 으로 대화 요청을 보내면
- **THEN** 응답이 완료되기 전부터 텍스트 증분과 도구 실행 이벤트가 순차적으로 전달되고, 마지막에 최종 결과 이벤트가 전달된다

#### Scenario: 알 수 없는 CLI 이벤트 처리
- **WHEN** CLI 가 시스템이 알지 못하는 형태의 이벤트를 출력하면
- **THEN** 해당 내용은 버려지지 않고 사용자가 볼 수 있는 형태로 전달되며, 스트림은 중단되지 않는다

### Requirement: 스트림 재접속과 이어보기
시스템은 진행 중인 실행에 대해 클라이언트가 재접속할 수 있는 경로를 제공하고, 재접속 시 이미 발생한 진행 내용을 이어서 볼 수 있게 해야 한다(SHALL). 재접속 대상 실행이 없으면 그 사실을 명확히 응답해야 한다(SHALL).

#### Scenario: 네트워크 끊김 후 재접속
- **WHEN** 스트리밍 중 연결이 끊긴 클라이언트가 같은 실행 식별자로 재접속하면
- **THEN** 끊긴 이후에도 진행된 내용을 이어서 받고 실행 완료까지 스트리밍이 계속된다

#### Scenario: 이미 종료된 실행에 재접속
- **WHEN** 이미 완료된 실행 식별자로 재접속을 요청하면
- **THEN** 진행 중인 스트림이 없음을 응답하고, 클라이언트는 저장된 대화 기록으로 화면을 복원할 수 있다

### Requirement: 대화 연속성
시스템은 같은 대화에서 이어지는 요청이 이전 맥락을 유지하도록 CLI 세션을 이어가야 한다(SHALL). 세션을 이어갈 수 없는 경우 처음부터 다시 시작한 사실을 사용자에게 알려야 하며(SHALL), 조용히 맥락을 잃은 채 진행하지 않아야 한다(SHALL NOT).

#### Scenario: 연속 대화
- **WHEN** 같은 대화에서 두 번째 메시지를 보내면
- **THEN** 에이전트는 이전 대화 내용과 이전에 만든 파일을 알고 있는 상태로 응답한다

#### Scenario: 세션 재개 불가
- **WHEN** 이전 세션이 만료되었거나 워크스페이스가 정리되어 이어갈 수 없으면
- **THEN** 새 세션으로 시작하되 직전 대화 요약이 맥락으로 제공되고, 이어가기가 실패했음이 사용자에게 표시된다

### Requirement: 대화 기록 저장
시스템은 각 턴이 끝나는 즉시 사용자 메시지와 에이전트 응답을 대화 기록으로 저장해야 한다(SHALL).

#### Scenario: 턴 종료 시 저장
- **WHEN** 한 번의 대화 턴이 끝나면
- **THEN** 해당 턴의 메시지가 저장되어 새로고침 후에도 대화 내용이 남아 있다
