## ADDED Requirements

### Requirement: 실행 중 사용자 확인 요청 발행
시스템은 CLI 에이전트가 실행 중 사용자 확인이나 추가 입력을 필요로 할 때, 담당자에게 확인 요청을 전달하고 실행을 대기 상태로 표시해야 한다(SHALL). 대기 중인 실행은 실패나 완료로 기록하지 않아야 한다(SHALL NOT).

#### Scenario: 승인이 필요한 작업
- **WHEN** 에이전트가 허용되지 않은 범위의 작업을 시도해 승인 요청 이벤트가 발생하면
- **THEN** 담당자에게 무엇을 승인해야 하는지 담긴 확인 요청이 전달되고, 업무는 사용자 응답 대기 상태가 된다

#### Scenario: 추가 정보 요청
- **WHEN** 에이전트가 업무 수행에 필요한 정보를 사용자에게 물으면
- **THEN** 질문 내용이 담당자에게 전달되고 실행은 대기 상태로 유지된다

### Requirement: 중복 확인 요청 억제
같은 실행에서 동일한 내용의 확인 요청이 반복되면, 시스템은 중복 요청을 새로 발행하지 않아야 한다(SHALL NOT).

#### Scenario: 동일 질문 반복
- **WHEN** 아직 응답되지 않은 확인 요청과 동일한 요청이 다시 발생하면
- **THEN** 새 요청이 추가로 발행되지 않고 기존 대기 요청이 유지된다

### Requirement: 응답 후 중단 지점부터 재개
시스템은 사용자 응답을 받으면 같은 워크스페이스에서 이전 실행 맥락을 이어 재개해야 한다(SHALL). 재개 실행은 이미 완료된 작업을 처음부터 반복하지 않아야 한다(SHALL NOT).

#### Scenario: 승인 후 재개
- **WHEN** 담당자가 확인 요청에 승인으로 응답하면
- **THEN** 같은 워크스페이스와 대화 맥락에서 실행이 재개되고, 이전에 만든 파일과 진행 내용이 유지된다

#### Scenario: 거부 응답
- **WHEN** 담당자가 확인 요청을 거부하면
- **THEN** 에이전트에게 거부 사실이 전달되어 대안을 진행하거나, 진행이 불가하면 업무가 사유와 함께 종료된다

### Requirement: 재개 불가 상황 처리
시스템은 대기 상태의 실행을 재개할 수 없는 경우(세션 만료, 워크스페이스 소실) 그 사실을 사용자에게 알리고, 사용자가 새 실행으로 이어갈 수 있게 해야 한다(SHALL).

#### Scenario: 대기 중 워크스페이스 정리됨
- **WHEN** 응답 시점에 이전 실행의 워크스페이스나 세션이 남아 있지 않으면
- **THEN** 이어가기가 불가함이 사용자에게 표시되고, 직전 맥락 요약을 포함한 새 실행 선택지가 제공된다

### Requirement: 대기 상태의 지속성
시스템은 서비스가 재시작되어도 대기 중인 확인 요청과 재개에 필요한 정보를 잃지 않아야 한다(SHALL NOT lose).

#### Scenario: 대기 중 서비스 재시작
- **WHEN** 확인 요청 대기 중에 서비스가 재시작된 뒤 담당자가 응답하면
- **THEN** 실행이 정상적으로 재개된다
