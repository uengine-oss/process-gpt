## ADDED Requirements

### Requirement: 실행 워크스페이스에 스킬과 지시문 주입
시스템은 업무 실행 전에 업무 지시문, 테넌트 스킬, 번들 시스템 스킬을 선택된 CLI 의 관례에 맞는 파일 배치로 실행 워크스페이스에 기록해야 한다(SHALL). 동일한 스킬 자산은 두 CLI 모두에서 사용 가능해야 한다(SHALL).

#### Scenario: Claude Code 관례로 주입
- **WHEN** 실행 CLI 가 `claude-code` 인 업무가 시작되면
- **THEN** 워크스페이스에 해당 CLI 가 읽는 루트 지시문 파일과 스킬 파일들이 생성되고, CLI 는 별도 조작 없이 그 스킬을 인식한다

#### Scenario: Codex 관례로 주입
- **WHEN** 동일한 스킬 자산으로 실행 CLI 가 `codex` 인 업무가 시작되면
- **THEN** 워크스페이스에 Codex 관례의 지시문 파일과 스킬 디렉터리가 생성되고, 각 스킬 파일에는 CLI 가 요구하는 이름·설명 메타데이터가 채워져 있다

### Requirement: 지원하지 않는 아티팩트의 명시적 보고
선택된 CLI 가 특정 아티팩트 종류를 지원하지 않으면, 시스템은 그것을 조용히 버리지 않고 건너뛴 항목으로 기록해야 한다(SHALL).

#### Scenario: 미지원 아티팩트 건너뜀
- **WHEN** 대응 배치 경로가 없는 아티팩트가 번들에 포함되어 있으면
- **THEN** 해당 아티팩트는 기록되지 않고, 건너뛴 항목 목록에 이름과 종류가 남아 실행 로그로 확인 가능하다

### Requirement: 테넌트 스킬 관리
시스템은 테넌트별 스킬을 조회·업로드·삭제할 수 있는 경로를 제공하고, 업로드된 스킬을 CLI 중립 원본으로 보관해야 한다(SHALL). 삭제된 스킬은 이후 실행 워크스페이스에 주입되지 않아야 한다(SHALL NOT).

#### Scenario: 스킬 업로드 후 즉시 사용
- **WHEN** 사용자가 테넌트 스킬을 업로드하고 새 업무를 실행하면
- **THEN** 업로드된 스킬이 그 실행의 워크스페이스에 주입되어 에이전트가 사용할 수 있다

#### Scenario: 스킬 삭제
- **WHEN** 사용자가 테넌트 스킬을 삭제하면
- **THEN** 이후 실행에서 해당 스킬이 워크스페이스에 나타나지 않는다

### Requirement: git 저장소 스킬 사용
시스템은 git 저장소로 지정된 스킬을 실행 전에 가져와 주입해야 하며(SHALL), 가져오기에 실패하면 실행을 중단하지 않고 실패한 스킬을 명시한 채 나머지 스킬로 계속 진행해야 한다(SHALL).

#### Scenario: git 스킬 가져오기 성공
- **WHEN** git 저장소가 지정된 스킬이 업무에 연결되어 있으면
- **THEN** 실행 전에 최신 내용이 가져와져 워크스페이스에 주입된다

#### Scenario: git 스킬 가져오기 실패
- **WHEN** git 저장소 접근이 실패하면
- **THEN** 해당 스킬만 제외되고 실행은 계속되며, 어떤 스킬이 왜 제외되었는지 실행 기록에 남는다

### Requirement: 시스템 스킬 전역 제공
시스템은 서비스에 번들된 시스템 스킬을 모든 테넌트 실행에 제공해야 하며(SHALL), 외부 네트워크 접근 없이도 사용 가능해야 한다(SHALL).

#### Scenario: 오프라인 환경의 시스템 스킬
- **WHEN** 외부 저장소에 접근할 수 없는 환경에서 업무가 실행되면
- **THEN** 번들 시스템 스킬은 정상적으로 워크스페이스에 주입되어 사용 가능하다
