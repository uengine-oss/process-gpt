## 1. 보관함 저장 계약 (`pgpt-pro_credential-vault`)

- [x] 1.1 데이터 마이그레이션(키 행의 DEK 버전·교체 시각, 항목 행의 구분 지문·표시용 메타·DEK 버전·사용 이력, 활동 기록 테이블)을 멱등 SQL 로 추가한다. 완료 기준: 두 번 적용해도 오류가 없고 기존 항목이 그대로 열린다.
- [x] 1.2 항목 종류·입력 검증(로그인 사이트/비밀번호, 카드 Luhn·만료일·CVC, API 키)과 한국어 `error` 응답을 구현한다. 검증 대상: "잘못된 카드 번호", "만료된 카드".
- [x] 1.3 구분 지문으로 사이트별 여러 계정·여러 장의 카드를 구분하고, 같은 계정은 갱신한다. 검증 대상: "같은 사이트의 두 계정", "두 장의 카드".
- [x] 1.4 비밀 값을 돌려주지 않는 조회·저장·수정 응답과 카드 라벨(`브랜드 •••• 끝4자리`)을 구현한다. 검증 대상: "카드와 로그인이 있는 보관함 조회".
- [x] 1.5 `PATCH /api/vault/:id`(일부 필드 수정, 상태 초기화, 같은 계정 충돌 409), `DELETE`, 사용자 격리(404)를 구현한다.
- [x] 1.6 `captured` 항목의 확인(`/confirm`, 같은 계정 대체)·폐기(`/discard`)와 자동 사용 제외를 구현한다. 검증 대상: "새 비밀번호 감지 후 확인", "확인 전에는 쓰이지 않음".
- [x] 1.7 활동 기록(행위자·필드 이름, 값 없음)과 `GET /api/vault/audit` 를 구현한다.
- [x] 1.8 `GET /api/vault/proof`(KEK/DEK 정보, 항목별 검사 6종, 값 없음)를 구현한다. 검증 대상: "검증 통과".
- [x] 1.9 테스트: 봉투 체인 독립 복호화, 비노출, AAD 바인딩, 여러 계정, 카드 검증, 감지·확인 (`pgpt-pro/server/test/vault.test.js`).

## 2. 브라우저 자격 증명 대리 처리 (`pgpt-pro_browser-credential-handoff`)

- [x] 2.1 로그인/카드가 없으면 보관함 요청 카드를 먼저 올리고 작업을 `needs_input` 으로 둔 뒤, 저장되면 이어서 진행한다. 검증 대상: "처음 가는 사이트에 로그인", "저장된 카드 없이 결제".
- [x] 2.2 여러 계정·카드일 때 라벨만 보이는 선택 카드와 작업 내 선택 기억, 무인 실행의 최근 항목 사용을 구현한다. 검증 대상: "카드 두 장 중 선택".
- [x] 2.3 모델 비노출 네 겹(스냅샷 비밀 칸 값 제거, 모델용 스크린샷 가림, 비밀 칸 직접 타이핑 거절, 입력값 재등장 지우기)과 실시간 화면 가림을 구현한다. 검증 대상: "로그인·OTP·결제 전 과정의 모델 요청 검사", "모델이 비밀번호 칸에 직접 입력 시도".
- [x] 2.4 `login_failed` 도구: 항목 `rejected` 표시, 갱신 카드, 갱신 후 재로그인. 검증 대상: "처음 입력한 비밀번호가 틀림".
- [x] 2.5 `need_secret` 도구와 `POST /api/vault/requests/:msgId/secret`: 저장하지 않고 페이지 칸에 바로 입력, 409 처리. 검증 대상: "휴대폰 인증 코드".
- [x] 2.6 요청 닫기(`/dismiss`)와 같은 작업 안에서 다시 묻지 않기. 검증 대상: "로그인 요청 닫기".
- [x] 2.7 직접 제어 중 제출 감지(페이지 감시 스크립트 + 서버 바인딩), 즉시 암호화된 `captured` 보관, 저장 확인 카드. 검증 대상: "다른 계정으로 직접 로그인".
- [x] 2.8 `approve` 도구와 승인 카드(요약 + 결제 카드 라벨, 승인/취소). 검증 대상: "결제 승인", "결제 취소".
- [x] 2.9 무인 실행에서 기다리지 않고 메모로 남기기, 응답 없는 요청과 재시작 시 대기 카드 만료, 만료 카드로의 제출 409.
- [x] 2.10 채팅 보관함 카드(로그인/카드/일회용 × 요청/갱신/감지, 닫기, 저장됨 칩), 승인 카드, 설정 계정·지갑 화면을 hark pro 흐름에 맞춰 구현한다.
- [x] 2.11 테스트: 모델 대역 서버로 로그인 요청·거부·OTP, 카드 요청·승인, 카드 선택, 직접 제어 감지, 요청 닫기 (`pgpt-pro/server/test/browser-vault.test.js`), 실제 앱·실제 모델 UI E2E (`e2e/ui-e2e.mjs`).

## 3. 키 관리 (`pgpt-pro_vault-key-management`)

- [x] 3.1 KEK 공급원(환경 변수 / 0600 키링 파일)과 32바이트 검사, 식별자, 단일 키 파일 가져오기를 구현한다. 검증 대상: "단일 키 파일에서 키링으로".
- [x] 3.2 KEK 교체(전체 재래핑, 항목 불변), 지연 재래핑, 환경 변수 공급원 거절과 안내를 구현한다. 검증 대상: "교체 후 항목은 그대로, DEK 만 다시 감쌈".
- [x] 3.3 폐기 KEK 정리를 구현한다. 검증 대상: "교체 후 정리".
- [x] 3.4 DEK 교체(트랜잭션 재암호화, 버전 증가, 버전 포함 AAD)를 구현한다. 검증 대상: "로그인과 카드가 있는 사용자의 DEK 교체".
- [x] 3.5 전수 검증(구분 지문 채우기 포함)과 운영 명령(`status`, `verify`, `rotate-kek`, `rewrap`, `prune-kek`, `rotate-dek`)을 제공한다. 검증 대상: "운영 데이터 검증".
- [x] 3.6 DEK 메모리 캐시 10분 제한·0 덮어쓰기, 키 작업 활동 기록을 구현한다.
- [x] 3.7 설정 > 보안 화면에 KEK/DEK 설명, 암호화 검증 결과, 보관함 활동을 표시한다.
