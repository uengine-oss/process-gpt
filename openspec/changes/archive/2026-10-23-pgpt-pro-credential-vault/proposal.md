## Why

pgpt-pro 는 hark pro 처럼 사용자를 대신해 웹사이트에 로그인하고 결제하는 브라우저 에이전트를 제공한다. 이때 비밀번호·카드 번호·인증 코드가 AI 모델이나 채팅 화면, 데이터베이스 평문으로 흘러가면 서비스 전체의 신뢰가 무너진다. 지금까지는 로그인 한 건을 보관함에 저장하는 최소 기능만 있었고 다음이 빠져 있었다.

- 결제 카드가 없을 때 사용자에게 받는 경로가 없었고, 카드를 두 장 이상 저장할 수 없었다(새 카드가 기존 카드를 덮어씀).
- 사이트가 비밀번호를 거부해도 상태가 기록되지 않았고, 사용자가 고칠 방법이 없었다.
- 인증 코드(OTP/SMS) 같은 일회용 값을 모델에 노출하지 않고 전달하는 경로가 없었다.
- 사용자가 직접 제어 중에 입력한 로그인이 보관함으로 들어오지 않았다.
- 페이지 스냅샷이 입력란 값을 그대로 모델에 보내, 채워 넣은 비밀번호가 다음 턴에 모델로 새어 나갈 수 있었다.
- KEK 가 하나뿐이라 교체할 방법이 없었고(교체하면 모든 데이터를 잃음), DEK 교체·전수 검증·활동 기록이 없었다.
- "봉투 암호화로 저장되고 있다"는 사실을 사용자나 운영자가 확인할 수단이 없었다.

## What Changes

- 보관함을 KEK → 사용자별 DEK → 항목의 봉투 암호화(AES-256-GCM) 계약으로 정식화한다. 암호문은 (사용자, 종류, 사이트)에 묶여 다른 맥락으로 옮기면 열리지 않는다.
- 사이트별 여러 계정, 여러 장의 카드를 평문 저장 없이 구분한다. 카드 입력은 번호(Luhn)·만료일·CVC 를 검증한다.
- 브라우저 에이전트가 로그인·카드·일회용 코드를 요구하는 페이지를 만나면, 시스템이 채팅 카드로 사용자에게서 값을 받아 보관함에 넣고(일회용 코드는 저장하지 않음) 서버에서 직접 입력한다. 모델에는 값이 전달되지 않는다.
- 비밀번호 거부 시 항목을 `rejected` 로 표시하고 갱신 카드를 띄운다. 저장 항목이 여럿이면 라벨만 보이는 선택 카드를 띄운다. 결제·전송·삭제 직전에는 금액과 카드 라벨이 담긴 승인 카드를 띄운다.
- 직접 제어 중 사용자가 제출한 로그인/카드를 즉시 암호화해 `captured` 로 보관하고, 사용자가 확인해야 정식 항목이 된다.
- 페이지 스냅샷·스크린샷·실시간 화면에서 비밀 입력란을 가리고, 작업 중 입력한 값이 모델 입력에 다시 나타나면 지운다.
- 키링(여러 KEK 버전), KEK 교체·지연 재래핑·정리, DEK 교체(항목 재암호화), 전수 검증 운영 명령을 제공한다.
- 보관함 활동 기록과, 값을 보여주지 않는 암호화 검증 조회(`GET /api/vault/proof`)를 제공하고 설정 > 보안 화면에 노출한다.

## Capabilities

### New Capabilities

- `pgpt-pro_credential-vault`: 로그인·카드·API 키·OAuth 토큰을 봉투 암호화로 저장하고, 비밀 값을 노출하지 않고 조회·수정·삭제·확인하며, 활동 기록과 암호화 검증을 제공하는 계약.
- `pgpt-pro_browser-credential-handoff`: 브라우저 에이전트가 만난 로그인·결제·일회용 코드 요구를 시스템이 대신 받아 보관함에 넣고, 모델에 노출하지 않고 입력하며, 거부·선택·승인·직접 제어 감지를 처리하는 계약.
- `pgpt-pro_vault-key-management`: KEK 공급원과 키 버전, KEK·DEK 교체, 폐기 KEK 정리, 전수 검증, 기존 데이터 호환을 보장하는 운영 계약.

### Modified Capabilities

없음. process-gpt 핵심 서비스의 기존 스펙은 바뀌지 않는다.

## Impact

- **서비스**: pgpt-pro BFF(:8787)의 보관함 API(`/api/vault*`)가 확장되고 오류는 `{error}` 와 4xx 로 응답한다. 브라우저 에이전트 도구에 `login_failed`, `need_secret`, `approve` 가 추가된다.
- **화면**: 채팅 보관함 카드(로그인/카드/일회용 코드 × 요청/갱신/감지), 승인 카드, 설정의 계정·지갑·보안(검증·활동) 화면.
- **데이터**: 보관함 키 테이블에 DEK 버전, 항목 테이블에 구분 지문·표시용 메타·사용 이력, 활동 기록 테이블이 추가된다(멱등 SQL 마이그레이션). 기존 항목은 그대로 열린다.
- **운영**: KEK 는 0600 키링 파일 또는 환경 변수로 공급하며 데이터베이스에 두지 않는다. 키 교체·검증은 운영 명령으로 수행한다.
- **보안**: 평문 비밀은 서버 메모리 안에서만 다루고, 화면·모델·로그·API 응답에 나타나지 않는다. 언래핑된 DEK 는 최대 10분만 메모리에 둔다.
