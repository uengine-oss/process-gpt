## Context

- 이음오피스는 데스크톱(Electron) 앱이다.
  - 편집기 화면(React)은 브라우저에서 그대로 돈다.
  - Electron에 묶인 것은 화면과 뒷단을 잇는 preload 다리와 뒷단(main) 코드뿐이다.
- 이음오피스는 upstream(GenOffice)의 문서 엔진 개선을 계속 받아온다. Process GPT도 그 개선을 계속 받고 싶다.
- Process GPT 프론트엔드는 Vue 3, 편집기는 React다.
- 채팅 에이전트(deepagents)는 테넌트 MCP 설정으로 외부 도구를 받는다. 사용자별 자격증명은 `{{user_jwt}}` 자리 표시로 넣는다.

이어받는 사람을 위한 안내(저장소·브랜치·실행·남은 일·함정)는 `services/office-host/HANDOVER.md`에 있다.

## Goals / Non-Goals

**Goals:**
- 한글·워드·엑셀·파워포인트·PDF를 원본 형식 그대로 열고 저장한다. 저장해도 원본은 남는다.
- 편집기 AI가 업무 맥락을 안다. AI는 회사 안의 언어 모델로 돈다.
- 에이전트가 문서를 고칠 수 있다. 사람이 열어 둔 문서는 그 사람이 보는 앞에서 고친다.
- 이음오피스 소스를 고치지 않는다.

**Non-Goals:**
- 문서 생성 경로를 바꾸지 않는다. 템플릿 채움·생성은 office-mcp가 그대로 맡는다.
- 데스크톱 전용 기능(숨은 창으로 하는 PDF 내보내기·인쇄, 운영체제 파일 대화 상자, 맞춤법·Zotero·Google 드라이브)은 이번 범위가 아니다.
- 사용자가 없는 백그라운드 실행에서의 문서 편집은 이번 범위가 아니다.

## Decisions

### 1. `electron` 모듈 하나만 바꿔 끼운다
- 브라우저 쪽 preload의 IPC는 WebSocket으로 보낸다.
- 서버 쪽에서는 이음오피스의 뒷단 코드를 Node에서 그대로 돌리고, IPC를 WebSocket으로 받는다.
- 데스크톱 앱의 사용자 정의 스킴은 HTTP 경로로 내준다.
- 대안: 편집기를 새로 만들거나 엔진만 떼어 쓰는 방법이 있었다. 둘 다 upstream 개선을 받을 수 없어 버렸다.

### 2. 한 서비스, 사이드카는 자식 프로세스
- 엑셀 엔진(Rust 사이드카)은 열린 통합 문서를 쥐고, 파워포인트는 뒷단 세션에 문서 모델이 있다.
- 이 상태를 별도 마이크로서비스로 떼면 포크를 고쳐야 하고, 셀마다 네트워크 왕복이 생긴다.
- 그래서 office-host 안의 자식 프로세스로 둔다. 늘릴 때는 인스턴스를 여럿 띄우고 문서 단위로 스티키 라우팅한다.

### 3. 문서 생성은 office-mcp, office-host는 읽기·편집만
- office-host의 도구는 호출한 사용자의 토큰으로 돈다.
- deepagents는 토큰이 없는 실행(백그라운드 업무 처리)에서 `{{user_jwt}}`를 쓰는 MCP 서버를 아예 빼고 실행한다.
- 생성을 office-host에 맡기면, 프로세스의 에이전트 단계에서 문서 생성이 조용히 빠진다.
- office-mcp는 서버 자격증명으로 올리므로 백그라운드에서도 돈다.
- 그래서 생성은 office-mcp에 두고, office-host는 사람이 있는 맥락(채팅·열린 편집기)의 읽기·편집만 맡는다.
- 대안: office-host에 서비스 토큰 경로를 열 수 있었다. 테넌트·담당자 확인을 새로 만들어야 해서 미뤘다.

### 4. 저장은 원본 옆의 편집본
- 원본 객체를 덮지 않고, 같은 위치에 `edited-<원본 객체 이름>_<시각>` 객체로 올린다.
- 저장소 키가 ASCII여야 해서 화면 이름 대신 객체 이름을 쓴다.
- 편집본을 다시 고치면 원래 이름을 유지한다(이름이 겹쳐 길어지지 않는다).

### 5. 업무 맥락은 화면이 넘기고 서버가 붙인다
- 업무 화면이 편집기 프레임에 업무 맥락(프로세스, 활동, 설명, 지시, 이전 단계 입력)을 메시지로 보낸다.
- 서버는 알려진 필드만 남기고 길이를 자른 뒤, 그 편집기 탭의 AI 요청 시스템 프롬프트 끝에 붙인다.
- 맥락의 문장이 사용자 요청과 부딪히면 사용자 요청을 따르게 적는다.

### 6. 실시간 공동 편집은 편집기의 기존 다리를 쓴다
- 이음오피스 편집기에는 데스크톱 셸이 명령을 보내면 열린 편집기가 내장 AI와 같은 실행기로 처리하는 다리가 이미 있다.
- office-host가 셸 역할을 해서 에이전트 명령을 열린 편집기로 보낸다.
- 에이전트가 쓰기 시작하면 업무 화면에 알림을 보낸다.
- 자리 표시를 채울 때는 블록 번호 대신 글로 찾아 바꾼다. 앞의 변경이 뒤 블록 번호를 밀기 때문이다.

### 7. 제품 이름과 고지
- Apache-2.0은 상표 사용권을 주지 않는다. 그래서 화면의 제품 이름과 AI 그림은 빌드할 때 Process GPT 오피스로 바꾼다. 원본 파일은 그대로 둔다.
- 함께 내는 고지는 편집기 서버의 고지 페이지와 이미지 안에 둔다. LICENSE, NOTICE, 제3자 고지, 한글과컴퓨터 공개 문서 문구다.

## Risks / Trade-offs

- **[토큰이 iframe 주소 쿼리에 실린다]** → 운영에서는 짧은 일회용 토큰으로 바꾼다. 지금은 HS256 비밀키 검증만 한다(비대칭 키를 쓰면 그 검증을 붙인다).
- **[편집기 탭 하나 = 서버 상태 하나]** → 인스턴스를 늘리면 WebSocket과 실시간 도구 호출을 같은 인스턴스로 보내는 스티키 라우팅이 필요하다.
- **[이미지 크기 약 2.5GB]** → 이음오피스 의존성 전체를 담아서다. 서버 번들에 npm 패키지를 넣으면 줄일 수 있다.
- **[upstream 변경]** → 빌드가 이음오피스의 두 곳(제품 이름 정의, CLI의 저장소 위치 찾기)에 기댄다. 바뀌면 빌드가 멈추며 알린다.
- **[에이전트의 인자 형식]** → 에이전트가 연산 배열을 JSON 문자열로 보내는 일이 있었다. 도구는 둘 다 받는다.

## Migration Plan

1. office-host 이미지를 배포한다(포트 5390, WebSocket 허용, 저장소·사내 LLM·토큰 검증 설정).
2. 프론트엔드에 `VITE_OFFICE_WEB_URL`을 준다. 비우면 기존 뷰어로 돌아간다(되돌리기).
3. 테넌트 MCP 설정에 `process-gpt-office`를 넣으면 채팅 에이전트가 도구를 쓴다. 빼면 도구가 사라진다.

## Open Questions

- 저장소를 비공개 버킷으로 바꿀 때 편집기와 도구의 주소를 서명 URL로 바꾸는 시점.
