## 질문: 맥락이 많아지면 무엇을 판단 모델에 주는가

두 방식을 검토했다.

1. **각 대화의 요약을 모두 주고 그중 하나를 고르게 한다**
2. **대화 이력을 통째로 선택지로 준다**

둘 다 규모가 커지면 성립하지 않는다.

- 선택지 문자(A~Z) 방식의 판단(open-alternative-jev, logprob)은 선택지가 26개를 넘을 수 없다.
- 선택지와 설명이 길수록 판단 지연이 커진다. 측정에서 25개, 약 1,600자일 때 2.3~2.6초였고, 6개, 약 450자일 때는 0.8~0.9초였다.
- 비슷한 대화가 많을수록 작은 판단 모델이 헷갈린다. 25개를 다 넣어도 300개 규모에서는 정확도가 57%에 그쳤다.

그래서 **"판단 모델에는 짧은 후보 몇 개만, 고르는 범위는 모델 없이 넓게"** 로 나눴다.

## 결정

### 1. 두 단계: 모델 없이 넓게 좁히고, 판단 모델은 좁게 고른다
- **1단계(저장소)**: 30일 넘게 잠든 맥락은 제외한다. 최근 200개와, 메시지 내용어로 제목·요지를 검색한 결과를 합친다. 이 검색이 없으면 3주 전 대화가 수백 개 뒤로 밀려 사라진다.
- **2단계(라우터, 수 ms)**: 진행 중 작업과 가장 최근 2개는 항상 남긴다. "그거 취소해" 처럼 가리키는 말만 있는 메시지는 거의 최근 일을 뜻하기 때문이다. 나머지는 점수로 채운다.
  - 단어 겹침: 한국어는 두 글자 단위로 비교하고, 사용자 맥락 안에서 드문 단어에 가중치를 둔다.
  - 의미 유사도(선택): 겹침 40%, 의미 60% 로 섞는다.
  - 약한 최근성.
  - 같은 제목의 반복 업무는 한 자리만 차지한다.
- 의미 유사도는 선택이다. 임베딩 엔드포인트가 없으면 단어 겹침만 쓴다(lex6). 측정에서 의미를 더하면 300개 규모에서 81% → 95%였다.

### 2. 오래될수록 짧게
- 하루 이내는 요지 + 최근 요청·답 160자, 일주일 이내는 요지 + 최근 요청 한 줄 100자, 그 이후는 60자다.
- 대화 이력 전체는 넘기지 않는다. 요약을 바꿀 때 이전 요청은 요지(`gist`, 120자, 최신 단어 우선)로 접어 남긴다. 이렇게 하면 LLM 호출 없이도 대화가 길어질수록 앞의 흐름이 단어로 남는다.
- 처음에는 일주일이 지난 맥락을 요지 50자만 보이게 했는데, 12일 된 SNS 대화의 "브랜치" 같은 결정적 단어가 빠져 오답이 생겼다. 그래서 요지에 최근 요청 첫 줄을 더해 60자로 완화했다.

### 3. 작은 판단 모델의 근거 없는 확신은 다시 판단
- 4B 판단 모델은 무관한 새 질문(점심, 엑셀, 노트북)을 엉뚱한 대화에 확신도 1.0 으로 붙이는 경향이 있다. 위치 편향이 그 원인 중 하나다.
- 고른 대화에 메시지와 겹치는 단어가 없고, 의미 유사도가 0.5 미만이며, 가리키는 말도 아니면 판단 모델을 건너뛰고(`Decider.decide(skip=("judge",))`) logprob 으로 다시 판단한다.
- "추천해줘 ↔ 추천을 요청함" 처럼 요청 동사가 겹치는 것은 근거로 치지 않는다(`_STOP_BI`).

### 4. 임베딩도 같은 원칙(설정되면 쓰고, 없으면 내려간다)
- 참조 판단 서버가 `EMBED_MODEL=BAAI/bge-m3` 로 OpenAI 형식 `/embeddings` 를 함께 제공한다. 운영에서는 OpenAI `text-embedding-3-small` 이나 vLLM 임베딩 모델로 바꿔도 된다.
- 맥락 벡터는 텍스트 해시로 프로세스 안에 캐시하므로, 라우팅 한 번에 새로 임베딩하는 것은 대개 새 메시지 하나다.

### 5. 브라우저 에이전트: 확실한 짧은 판단만 큰 모델 대신
- **페이지 상태(새 URL에서 한 번)**: 로딩이면 큰 모델 없이 1.5초 기다려 다시 읽는다(최대 2회). 무인 실행에서 로그인 벽이나 캡차이면 큰 모델에게 우회하라고 미리 알린다. 그래서 need_login → 거절 → 우회로 이어지는 턴을 아낀다.
- **목표 달성(사실 기록 때마다)**: 확신도 0.9 이상으로 "다 모았다"면 `finish` 를 강제한 한 번의 호출로 끝낸다.
- 측정된(calibrated) 확신도만 따른다. JSON 전략의 자기 보고 확신도로는 행동을 바꾸지 않는다.
- 판단에 넘기는 글은 보관함 값을 가린 뒤의 글이다(`hide`).

## 측정 요약
- **맥락 라우팅**: 무관한 대화 300개에서 정확도는 기존 52%, 전부 넣기 57%(2.3초), 좁히기 95%(0.8초)였다. 0·25·100개에서는 좁히기가 90%였다.
- **브라우저 게이트(3과제 × 3회)**: 턴이 14.0 → 11.0(−21%), 큰 모델 호출이 15.0 → 12.7(−15%)로 줄었고, 정답은 8/9 로 같았다.

## 트레이드오프와 남은 일
- **저장소 벡터 검색**: 저장소 검색은 단어(ilike)뿐이다. 단어가 하나도 겹치지 않으면서 최근 200개 밖에 있는 맥락은 찾지 못한다. 측정에서 300개 규모의 "세금계산서 → 부가세" 1건이 그랬다. `context_threads` 에 임베딩 열(pgvector)을 두고 저장소에서 유사도 상위를 가져오는 것이 다음 단계다.
- **요지 생성**: 요지는 단어 누적이다. 대화가 아주 길면 LLM 한 줄 요약으로 바꾸는 것을 고려한다. 비용은 대화당 갱신마다 작은 모델 1회다.
- **시간 지표**: 브라우저 게이트의 시간 효과는 회차 편차(40턴 한도 실패 회차)에 가려 이번 측정으로는 판단하지 않는다. 같은 과제를 더 많이 반복하거나, 실패 회차를 따로 분리한 측정이 필요하다.
- **판단 모델의 위치 편향**: 판단 모델의 위치 편향은 재판단으로 보정했다. 판단 모델 자체를 8B 이상으로 키우면 재판단 비율이 줄 것으로 본다.
