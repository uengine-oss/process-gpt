# 역할 기반 알림 검증 (e2e)

## 실행 환경
- 인프라: Supabase(local). process-gpt 의 `notifications` 테이블과 todolist 트리거는 그대로 사용한다.
- 소스로 실행한 서비스:
  - completion(8099) + polling, deepagents(8888), cli-agent(8890, Claude Code)
  - pgpt-pro BFF(8787), pgpt-pro 웹(5180)
- pgpt-pro 테이블: `server/sql/006_team_notify.sql` (`pro_team_members`, `pro_role_assignments`)
- 사용자 두 명:
  - 장진영(`pro-team-owner@uengine.org`): 프로세스를 시작함, 마케팅 담당자 역할은 지정 없음
  - 김민지(`pro-team-minji@uengine.org`): 제품 책임자로 지정

## 시나리오
1. 장진영이 설정 → 팀·역할에서 김민지를 팀원으로 추가하고, "제품 책임자" 담당자로 지정한다.
2. 장진영이 SNS 트렌드 데일리 대응을 시작한다. 흐름: 피드 스캔 → 신호 분류(`fit=접목`) → 벤치마킹 분석.
3. "제품 책임자 결정" 이 김민지에게 배정된다.
   - 김민지의 홈에 "결정" 카드가 반영·보류 버튼과 함께 뜬다.
   - 장진영의 홈에는 그 카드가 뜨지 않는다.
4. 장진영이 채팅에서 "김민지님께 같이 봐달라고 알려줘", "제품 책임자한테 확인해 달라고 알려줘" 라고 보낸다.
   - 김민지에게 "요청" 카드가 생긴다. 본문에 직전 대화 발췌가 들어 있다.
5. 김민지가 홈 카드에서 **반영** 을 누른다.
   - 결정 양식이 `decision=반영` 으로 제출된다.
   - 제품 개선 구현(Claude Code, worktree)과 구현 시연 영상이 이어진다.
6. "마케터 승인" 이 지정 없음 규칙에 따라 시작한 장진영에게 간다.
   - 장진영의 홈 카드에서 **승인** 을 누르면 인스턴스가 `COMPLETED` 가 된다.

## 증거
- `db-evidence.log`: 사용자, 역할 지정, 인스턴스 `role_bindings`, 단계별 담당자(`todolist.user_id`), 이 인스턴스의 알림 행, 요청(mention) 행, 최종 상태.
  - 사람 단계 알림은 각각 한 행이다. 제품 책임자 결정 → 김민지, 마케터 승인 → 장진영.
  - 나머지 작업 항목 알림은 에이전트 계정 앞으로 가서 사람에게 보이지 않는다.
- `../docs/role-notifications-demo.mp4`: 시연 영상(2분 21초, 나레이션). 두 사람 화면을 번갈아 보여 주고, Claude Code 동작 보기와 그 에이전트가 만든 시연 영상도 들어 있다.
- 서버를 재시작한 뒤에도 알림 목록이 그대로 나오는 것을 확인했다. 알림은 메모리가 아니라 `notifications` 에서 읽는다.

## 발견해 고친 것
- **대화 발췌**: `history()` 가 메시지 id 를 주지 않아서 이전 요청과 응답 문장이 발췌에 섞였다. 위치와 응답 문장 기준으로 거르도록 고쳤다.
- **카드 요지 한 줄**: 연락 초안의 제목이나 브랜치 이름이 뽑혔다. 그래서 마크다운 제목·식별자·JSON·링크를 빼고, 요지형 필드(`fit_reason`, `summary`, `rationale`)를 먼저 쓰도록 바꿨다.
- **이름 동기화**: 프로필 이름이 process-gpt `users.username` 에 없어 팀원에게 이메일 앞부분으로 보였다. 프로필 저장 때 함께 바꾼다.
- **카드에서 결정한 단계의 잔상**: 카드에서 결정한 직후, 엔진이 따라잡기 전 몇 초간 같은 단계가 홈의 작업 항목 버튼으로 다시 보였다. 이제 숨긴다.
