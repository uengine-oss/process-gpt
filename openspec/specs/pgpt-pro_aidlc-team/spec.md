# AI-DLC 팀 세션 (Robo-DLC Lite P1)

## Purpose

AI-DLC로 일하는 팀이 Process GPT Lite 안에서 같이 일한다. 공유 폴더(AI-DLC 저장소)마다 대화형 Claude Code 세션 하나를 띄워 구성원 모두가 같은 화면을 보고, AI-DLC가 사람을 기다리는 곳(질문에 답하는 방식, 질문 파일의 답, 요약 확인, 단계 승인, 도구 권한)은 그 단계를 맡은 역할의 사람에게 홈 카드로 간다. 사람은 결정 화면에서 고르거나 몹 회의에서 팀이 합의한 답을 확인해 적고, 그 결정은 세션의 선택 창에 그대로 들어가 AI-DLC 감사 기록에 사람의 답으로 남는다. 대시보드(`pgpt-pro_aidlc-dashboards`)는 같은 기록을 읽는다.

## Requirements

### Requirement: 폴더의 팀 세션은 구성원이 함께 보고, 편집 권한 이상만 입력한다

시스템은 AI-DLC 기록이 있는 공유 폴더마다 대화형 Claude Code 세션 하나를 그 저장소의 작업 사본에서 띄울 수 있어야 한다(SHALL). 세션은 폴더 편집 권한 이상인 사람만 시작하고, 구성원은 모두 작업실에서 같은 화면을 보며, 보기 권한인 사람은 읽기만 한다. 세션은 보는 사람이 없거나 서버가 다시 시작해도 이어진다. 세션은 기본 권한 모드로 시작해, 프로젝트가 허용하지 않은 도구는 사람이 답하는 권한 창에서 멈춘다.

#### Scenario: 보기 권한은 읽기만

- **WHEN** 보기 권한인 구성원이 폴더의 팀 세션을 작업실에서 연다
- **THEN** 세션 화면이 보이고 "보기만 해요" 표시가 있으며, 그 사람의 입력은 세션에 들어가지 않는다
- **AND** 그 사람이 세션을 시작하거나 결정을 보내면 403으로 거절된다

#### Scenario: 서버가 다시 시작해도 세션이 이어진다

- **WHEN** 팀 세션이 질문을 기다리는 동안 서버가 다시 시작한다
- **THEN** 세션과 그 화면은 그대로 있고, 다시 연 사람은 같은 화면을 본다

#### Scenario: 코드가 만들어지는 중에 쉘에서 지시한다

- **WHEN** 편집 권한인 개발자가 코드 생성 중인 팀 세션을 작업실에서 열고 "할 일 제목은 100자까지만 받고, 넘으면 화면에 이유를 보여 주세요."를 적는다
- **THEN** 그 글이 세션에 들어가고, Claude Code 는 하던 일을 마친 뒤 그 글을 다음 메시지로 받는다
- **AND** AI-DLC 는 그 글을 사람의 요청으로 기록하고, 다음 코드 계획 승인 창에 그 규칙을 올린다

### Requirement: 역할표는 폴더 구성원에게만 준다

시스템은 폴더마다 AI-DLC 역할(팀 리드, PO·기획, 아키텍트, 개발자, QA 등)을 맡은 사람을 둘 수 있어야 한다(SHALL). 역할은 폴더 편집 권한 이상인 사람이 정하고, 폴더 구성원에게만 줄 수 있다.

#### Scenario: 구성원이 아닌 사람에게 역할

- **WHEN** 팀 리드가 폴더 구성원이 아닌 사람을 아키텍트로 정하려 한다
- **THEN** 400으로 거절되고 역할표는 바뀌지 않는다

### Requirement: 사람을 기다리는 것은 그 단계 역할의 사람에게 카드 한 장으로 간다

시스템은 팀 세션 화면에 선택 창(답하는 방식, 요약 확인, 단계 승인, 도구 권한)이 뜨거나, 지금 단계의 질문 파일에 빈 답이 있으면, 그 단계 역할을 맡은 사람(맡은 사람이 없으면 폴더 소유자)에게 홈 카드를 한 번 보내야 한다(SHALL). 구현 단계의 도구 권한은 개발자에게 간다. 그 기다림이 끝나면 카드는 홈에서 내려간다. 요약 확인은 세션의 선택 창으로 묻기 때문에 질문 카드로 따로 보내지 않는다.

#### Scenario: 요구사항 단계의 승인 창

- **WHEN** 요구사항 단계에서 세션 화면에 단계 승인 선택 창(Approve · Request Changes)이 뜬다
- **THEN** PO 역할의 사람에게 "요구사항 승인" 카드가 가고, 팀 리드에게는 가지 않는다

#### Scenario: 기다림이 끝나면 카드가 내려간다

- **WHEN** 승인 창이 세션 화면에서 사라진다
- **THEN** 그 카드는 PO의 홈에서 내려가고, 빈 답이 남은 질문 파일이 있으면 "질문 N개가 답을 기다려요" 카드가 새로 간다

#### Scenario: 코드 생성 중 도구 권한

- **WHEN** 코드 생성 단계에서 Claude Code 가 명령 실행 권한을 묻는다
- **THEN** 개발자에게 카드가 가고, 카드와 결정 화면에 어느 도구인지와 실행할 명령이 보인다
- **AND** 공유 세션을 자동 모드로 바꾸는 선택지는 결정 화면에 없다

### Requirement: 선택 창 없이 대화로 물은 것도 기다림이다

시스템은 세션 화면에 선택 창이 없고 지금 단계의 질문 파일에 빈 답도 없는데 세션이 멈춰 입력을 기다리면, 세션이 마지막에 한 말을 그 단계 역할의 사람에게 카드로 보내야 한다(SHALL). 세션은 Claude Code 훅으로 멈춘 순간과 그 말을 알린다. 훅이 없으면 입력창이 빈 채로 같은 화면이 몇 초 동안 이어질 때 화면의 마지막 말로 판단한다. 세션이 일하는 중이거나, 누가 입력창에 글을 적는 중이거나, 작업이 끝났으면 기다림이 아니다. 결정 화면은 세션의 말에서 고를 수 있는 답(굵은 번호 목록, 「done」 같은 답할 말)을 단추로 보이고, 고른 말이나 사람이 적은 글을 세션 입력창에 그대로 넣는다. 아무것도 묻지 않고 멈춘 세션에는 「계속 진행해 주세요」를 권한다. 모든 답은 결정 기록에 남는다.

#### Scenario: 대화로 물은 승인

- **WHEN** 빌드와 테스트 단계에서 세션이 선택 창 없이 「Build and Test를 승인할까요? 1. **Approve** 2. **Request Changes**」라고 말하고 멈춘다
- **THEN** 그 단계 역할의 사람에게 「승인을 기다려요」 카드가 가고, 결정 화면에 세션의 말과 Approve · Request Changes 단추가 보인다
- **AND** Approve를 누르면 세션 입력창에 「Approve」가 들어가고 결정 기록에 남는다. 세션이 다시 일하면 카드가 내려간다

#### Scenario: 글이 필요한 선택지

- **WHEN** 결정 화면에서 「Request Changes」 단추를 누른다
- **THEN** 바로 보내지 않고 입력칸에 「Request Changes: 」를 채워 사람이 무엇을 바꿀지 적게 한다

#### Scenario: 말하고 멈춘 세션

- **WHEN** 세션이 「다음 단계인 코드 생성으로 넘어가겠습니다.」라고 말하고 멈춘다
- **THEN** 「멈춰 있어요」 카드가 가고, 결정 화면에 「계속 진행해 주세요」 단추가 보인다

#### Scenario: 훅이 알리면 곧바로

- **WHEN** 세션의 Stop 훅이 멈춘 순간의 말을 이 서버에 알린다
- **THEN** 다음 감시 차례를 기다리지 않고 몇 초 안에 카드가 간다
- **AND** 서명이 맞지 않거나 이 컴퓨터 밖에서 온 알림은 403으로 거절된다

#### Scenario: 일하는 중이거나 적는 중

- **WHEN** 세션 화면에 도는 스피너가 있거나, 입력창에 누가 적은 글이 남아 있다
- **THEN** 카드가 가지 않는다

### Requirement: 결정 화면에서 고른 것이 세션의 선택 창에 그대로 들어간다

시스템은 결정 화면에서 세션 화면의 선택 창과 같은 선택지를 보여 주고, 사람이 고른 번호를 그 선택 창에 그대로 넣어야 한다(SHALL). 결정은 그 단계 역할의 사람이나 폴더 편집 권한 이상인 사람만 하고, 사람이 본 화면과 지금 화면이 다르면 409로 거절한다. 글로 답하는 선택지는 사람이 적은 글을 함께 넣는다. 모든 결정은 폴더의 결정 기록에 남는다.

#### Scenario: PO 가 승인한다

- **WHEN** PO 가 홈 카드의 「결정하기」로 결정 화면을 열고 Approve 를 누른다
- **THEN** 세션의 선택 창에 1이 들어가고, 결정 기록 맨 위에 그 승인이 남는다

#### Scenario: 그새 바뀐 화면

- **WHEN** 결정 화면을 연 뒤 세션 화면의 선택 창이 바뀌었고, 그 사람이 예전 선택지로 결정을 보낸다
- **THEN** 409로 거절되고 세션에는 아무것도 들어가지 않는다

#### Scenario: 수정 요청과 그 글

- **WHEN** 아키텍트가 도메인 설계 승인 창에서 "Request Changes: …" 글을 적어 보낸다
- **THEN** 세션의 글 선택지에 그 글이 들어가고, AI-DLC 는 단계를 고쳐 다시 승인을 기다린다

### Requirement: 질문 파일의 빈 답만 적고, 세션에 알린다

시스템은 결정 화면에서 지금 단계 질문 파일의 빈 답에 사람이 고른 답을 적고, 세션이 떠 있으면 답을 적었다고 알려야 한다(SHALL). 이 작업 기록의 질문 파일만 적을 수 있고, 다른 경로는 404로 거절한다.

#### Scenario: 질문 세 개의 답

- **WHEN** PO 가 결정 화면에서 요구사항 질문 3개의 답을 골라 「파일에 적고 세션에 알리기」를 누른다
- **THEN** 질문 파일의 세 `[Answer]:` 줄에 그 답이 적히고, 질문 카드는 내려간다

#### Scenario: 기록 밖 경로

- **WHEN** 질문 파일 대신 `../../../../etc/hosts` 에 답을 적으려 한다
- **THEN** 404로 거절된다

### Requirement: 몹 회의에서 합의한 답을 담당자가 확인해 적는다

시스템은 결정 화면의 「몹 회의 열기」로 역할을 맡은 사람들의 그룹 대화방에 지금 단계의 질문을 올리고, 그 방에서 열린 화상 회의가 끝나면 받아쓰기와 회의록에서 팀이 분명히 합의한 답만 골라 결정 화면에 미리 채워야 한다(SHALL). 정하지 못한 질문은 채우지 않는다. 그 단계 역할의 사람에게 카드가 가고, 그 사람이 확인해 적으면 카드는 내려간다. 역할을 맡은 사람이 둘보다 적으면 회의를 열지 않는다.

#### Scenario: 몹 정교화

- **WHEN** 팀 리드·PO·아키텍트·개발자가 몹 회의에서 의도 정리 질문 6개 중 5개의 답을 말로 정하고, 6번째는 다음에 정하자고 한 뒤 회의를 끝낸다
- **THEN** 회의록이 방에 남고, 결정 화면에 답 5개가 회의에서 누가 어떻게 말했는지와 함께 채워지며 6번째는 비어 있다
- **AND** PO 에게 "몹 회의에서 답 5개를 정했어요" 카드가 간다

## 운영 제약

- 세션은 서버 컴퓨터의 Claude Code 로그인으로 돈다. 팀원 여럿이 한 세션을 함께 쓰는 것은 그 계정의 이용 조건 안에서만 한다.
- 선택 창은 세션 화면의 글자로 읽는다(Claude Code 2.1.x 의 "Enter to select · Esc to cancel"). 문구가 바뀌어 읽지 못하면 카드는 가지 않고, 사람은 작업실에서 직접 답한다.
- 감시는 기본 8초 간격이다. 카드는 그만큼 늦게 갈 수 있다. 세션을 띄울 때 넘긴 훅이 멈춘 순간을 알리면 그 폴더를 바로 다시 본다.
- 훅 설정 파일과 서명 키는 프로젝트 밖(서버 사용자의 홈)에 두고, 팀 저장소의 설정 파일에는 쓰지 않는다. 훅 주소는 세션을 띄운 서버의 포트에 묶이며, Claude Code 는 실행 중에 설정 파일을 다시 읽지 않는다 — 서버 포트가 바뀌면 세션을 다시 띄운다.
