### 시험을 돌리며 고친 결함
- (v0.3) 회사 지도의 일 화면에 습관 원문이 보였다 → 습관 이름 기록은 일 화면에서 뺐다. 역할 화면이 공개 기준을 무시했다 → 지도와 같은 기준.
- (v0.3) 「함께」 갈래가 95/5 처럼 하나만 고르는 경우에도 붙었다 → 두 순서가 모두 잦고 각 갈래가 15% 이상일 때만.
- (v0.3) 메일 처리 쪽 인계에 모델이 짐작한 역할(「영업 담당」)이 따로 역할로 생겼다 → 회사에 없는 역할 이름이면 그 사람의 지정 역할.
- (§15) 날짜 주기만으로 보니 건이 이끄는 일(고객 회신 · 평면도 작성)이 「평일 13시」 타이머로 잡혔다 → 같은 상대 · 비슷한 시각 · 주기 한 칸에 한 번.
- (§15) 주간 보고를 부탁하거나 약속한 메일의 주기가 그 메일의 일(요청 메일 접수 · 고객 회신)에 붙었다 → 반복되는 그 일(recur.task)에만.
- (S4) 「견적서에 회사 도장 찍어 줘」는 모델이 「물어봐도 되나」를 0.47~0.62 로 읽어(기준 0.7) 묻지 않았다 → 시드 말을 「합계 아래에 회사 직인 이미지 넣어 줘」(0.78~0.80)로. 도장을 「찍는」 습관은 덜 묻는다는 한계로 남긴다.
- (S2) 초안 모드에서는 엔진이 담당자 목록 맨 앞에 에이전트를 넣어 시험이 담당자를 잘못 읽었다 → 에이전트가 아닌 사람을 읽는다.
- 지난 실행의 같은 이름 파일이 작업 공간에 있으면 에이전트가 확인만 하고 끝나 단계가 실패했다 → 이 건의 파일을 새로 만들게 했다.
- LibreOffice 가 글꼴이 섞인 칸을 rich text 로 저장해 점검이 빈칸으로 읽혀 6개 중 5개가 ✗ 였다 → 사람이 보는 글자로 읽는다(단위 시험).
- 조건부 노화로 바꾸며 「최근 0일 동안」으로 나왔다 → 실제 날 수.
- 서버가 도는 동안 바깥에서 그래프를 지우면(데모 초기화) 지도가 오류였다 → 그래프를 다시 만들어 빈 지도(S1 첫 단계에 추가, 손으로 확인: 초기화 직후 200 · 일 0).
- 메일 읽기 첫 몇 분이 「0통 읽음」에 멈춰 보였다 → 거른 메일을 곧바로 세고, 채팅 이름 맞추기 단계라고 알린다.

### Ontological 에서 만난 제약(원본 저장소에 알릴 것)
- 시간 이력을 켠 키 있는 타입에서 `UNWIND … MERGE` 로 이미 있는 노드를 고치면 키 중복(`uq_…_p_key`)이 난다 → `UNWIND MATCH … SET` 과 `UNWIND CREATE` 로 나눠 쓴다.
- `MERGE … WITH … MERGE (관계)` 를 한 문장에 쓸 수 없다, `id` 속성은 내부 id 와 겹친다(→ `key`), 숫자 속성은 float8 로 선언해야 한다, 라벨 없는 패턴은 시점 질의를 거절한다.
