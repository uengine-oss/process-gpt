# office-host_original-format-editing Specification

## Purpose

업무 화면과 채팅에 첨부된 한글·워드·엑셀·파워포인트·PDF 문서를 화면용 페이지로 바꾸지 않고 원본 형식 그대로 열어 고치고, 저장하면 원본을 남긴 채 편집본을 업무 흐름에 넘긴다. 편집기 주소를 설정하지 않은 배포는 기존 뷰어로 동작한다. 편집기는 이음오피스(Apache-2.0)를 바탕으로 하며 고지를 함께 제공한다.

## Requirements
### Requirement: 첨부 문서를 원본 형식 그대로 열기

업무 화면의 첨부 카드나 채팅의 문서 패널에서 문서를 열면, 한글(hwp·hwpx)·워드(docx)·엑셀(xlsx)·파워포인트(pptx)·PDF·마크다운·HTML 문서는 화면용 페이지로 바뀌지 않고 원본 형식 그대로 편집기에서 열려야 한다(SHALL). 편집기 주소(`VITE_OFFICE_WEB_URL`)가 설정되지 않은 배포에서는 기존 문서 뷰어가 그대로 동작해야 한다(SHALL).

#### Scenario: 업무 화면에서 한글 기안 편집
- **GIVEN** 업무 화면의 파일 입력에 한글 문서가 첨부되어 있다
- **WHEN** 사용자가 첨부 카드의 편집을 누른다
- **THEN** 제목의 글꼴·색, 표, 그림, 쪽 여백이 원본 그대로 그려진 편집기가 열리고, 편집기 상태 줄에 열린 파일 이름이 보인다

#### Scenario: 다른 형식도 같은 편집 카드
- **GIVEN** 업무 화면의 파일 입력에 워드·엑셀·파워포인트·PDF 문서가 첨부되어 있다
- **WHEN** 사용자가 첨부 카드를 본다
- **THEN** 각 문서에 다운로드·미리보기·편집이 보이고, 편집을 누르면 그 형식의 편집기가 열린다

#### Scenario: 편집기 주소가 없는 배포
- **GIVEN** `VITE_OFFICE_WEB_URL`이 비어 있다
- **WHEN** 사용자가 한글 문서 첨부를 연다
- **THEN** 기존 뷰어가 열리고 동작이 바뀌지 않는다

### Requirement: 저장하면 원본 옆에 편집본을 남기기

편집기에서 저장하면 원본 객체는 바뀌지 않아야 하며(SHALL), 같은 저장소 위치에 `edited-<원본 객체 이름>_<시각>.<확장자>` 객체로 편집본이 올라가야 한다(SHALL). 편집기는 업무 화면에 새 주소를 알려야 하고, 업무 화면의 첨부 값은 편집본 주소로 바뀌어야 한다(SHALL). 편집본을 다시 고쳐 저장해도 이름에 `edited-`가 겹쳐 붙지 않아야 한다(SHALL).

#### Scenario: 기안 작성 단계에서 저장
- **GIVEN** 담당자가 업무 화면에서 한글 기안을 편집기로 열어 고쳤다
- **WHEN** 담당자가 편집기에서 저장한다
- **THEN** 저장 알림이 뜨고, 첨부 카드에 "편집본 · 다운로드"가 표시되며, 저장소에는 원본과 편집본이 둘 다 있다

#### Scenario: 다음 단계가 편집본을 받음
- **GIVEN** 담당자가 편집본을 저장하고 업무를 제출했다
- **WHEN** 결재자가 결재 단계 화면에서 이전 단계 입력 내역을 펼친다
- **THEN** 첨부된 문서는 원본이 아니라 편집본이다

#### Scenario: 편집본을 다시 고침
- **GIVEN** 첨부가 이미 편집본이다
- **WHEN** 사용자가 그 편집본을 열어 고친 뒤 저장한다
- **THEN** 새 편집본의 이름은 `edited-<원본 객체 이름>_<새 시각>` 꼴이고 `edited-edited-`로 시작하지 않는다

### Requirement: 미리보기는 저장해도 업무에 올리지 않기

미리보기로 연 문서는 편집기 안에서 저장하더라도 저장소에 편집본을 올리거나 업무의 첨부 값을 바꾸지 않아야 한다(SHALL).

#### Scenario: 결재자의 미리보기
- **GIVEN** 결재자가 이전 단계 내역의 문서를 미리보기로 열었다
- **WHEN** 결재자가 문서를 고치고 저장 단축키를 누른다
- **THEN** 저장소에 새 객체가 생기지 않고 첨부 값도 그대로다

### Requirement: 넓혀서 편집하기

편집 대화 상자의 편집기는 최대화(대화 상자를 창 가득)와 전체 화면을 제공해야 하며(SHALL), 원래 크기로 되돌릴 수 있어야 한다(SHALL).

#### Scenario: 최대화
- **WHEN** 사용자가 편집기 위쪽의 최대화를 누른다
- **THEN** 대화 상자가 창 너비와 높이를 가득 채우고, 단추가 원래 크기로 바뀐다

### Requirement: 로그인한 사용자와 허락된 문서만

편집기 연결은 로그인한 사용자의 토큰이 확인될 때만 열려야 한다(SHALL)(`SUPABASE_JWT_SECRET`이 설정된 배포). 편집기가 내려받는 문서 주소는 허락된 출처(`IEUM_ALLOWED_SOURCES`)여야 하며(SHALL), 페이지가 그 편집기 세션의 작업 폴더 밖 경로를 열거나 쓰려 하면 거절해야 한다(SHALL). 편집본은 로그인한 사용자의 저장소 권한(또는 설정된 서비스 키)으로 올려야 한다(SHALL).

#### Scenario: 토큰 없는 연결
- **WHEN** 토큰 없이 편집기 주소를 연다
- **THEN** 편집기 연결이 거절된다

#### Scenario: 허락되지 않은 출처
- **WHEN** 허락되지 않은 출처의 문서 주소로 편집기를 연다
- **THEN** 문서가 열리지 않고 오류가 표시된다

#### Scenario: 작업 폴더 밖 경로
- **WHEN** 편집기 페이지가 작업 폴더 밖의 파일 경로를 열거나 저장하려 한다
- **THEN** 요청이 거절되고 그 파일은 읽히거나 바뀌지 않는다

### Requirement: 제품 이름과 오픈소스 고지

편집기 화면은 제품 이름을 Process GPT 오피스로 표시해야 한다(SHALL). 편집기 서버는 `GET /office/licenses/`에서 오픈소스 고지 페이지를 제공해야 하며(SHALL), 이 페이지에서 Apache License 2.0 전문, 원저작자 NOTICE, 제3자 고지, 한글과컴퓨터 공개 문서 문구를 볼 수 있어야 한다(SHALL).

#### Scenario: 고지 페이지
- **WHEN** 사용자가 `/office/licenses/`를 연다
- **THEN** 읽을 수 있는 고지 페이지가 열리고, 바탕이 된 오픈소스와 그 라이선스, 함께 내는 고지 파일 링크, "본 제품은 한글과컴퓨터의 한글 문서 파일(.hwp) 공개 문서를 참고하여 개발하였습니다." 문구가 보인다
