# 가드레일이 글을 읽는 순서

## Purpose
회사 정책은 규칙으로 결정한다. 그 규칙에 넣을 값 가운데 글의 뜻을 읽어야 하는 것(이 맥락이 민감한가, 이 메일이 기밀인가)은 모델이 첫 토큰 확률(logprob)로 읽는다. 낱말 목록은 돌려 말한 글을 놓치고 뜻이 다른 글을 잡기 때문에, 모델이 답하지 못할 때만 대신한다. 모델은 값만 내고, 묻기·허용·거부는 정책 엔진이 정한다.

## Requirements

### Requirement: 맥락은 주민번호 형식 → 모델 → 낱말 순서로 읽는다

시스템은 팀원 맥락의 제목·한 줄 목적·맥락 요약을 다음 순서로 읽어 정책의 값 `topic` 을 만들어야 한다(SHALL).

1. 주민등록번호 형식이 보이면 모델을 부르지 않고 「주민등록번호」를 주제로 삼는다. 값 자체는 원장에 남기지 않는다.
2. 그 밖에는 모델이 글을 읽어 민감할 확률을 낸다. 확률이 0.5 이상이면 회사 주제 목록에서 가장 가까운 이름을 주제로 삼고, 고르지 못하면 「민감한 사항」이다. 0.5 미만이면 낱말이 있어도 주제가 없다.
3. 모델이 답하지 못하면 계좌번호·휴대전화 형식과 회사 주제 목록의 낱말이 대신한다.

계좌번호·휴대전화 형식은 양식 예시·주문번호·서명에도 걸리므로 앞에 두지 않고, 값을 가린 글을 모델이 읽어 정한다.

- 모델로 보내는 글에서 메일 주소 같은 형식 있는 개인정보는 가린다.
- 주인이 민감 표시를 했거나 제안을 무시한 맥락은 읽은 값을 쓰지 않는다. 회사가 정책 「민감할 수 있는 주제는 자동 허용하지 않음」을 끄면 읽지 않는다.

#### Scenario: 돌려 말한 민감한 글
- **GIVEN** 박하늘의 맥락 「최 대리 권고사직 면담 메모」, 주제 목록의 낱말은 없고 같은 팀은 자동 허용이다
- **WHEN** 같은 팀 이도윤이 원문 참고를 요청한다
- **THEN** 요청은 `pending` 이고 걸린 정책은 「민감할 수 있는 주제는 자동 허용하지 않음」이다
- **AND** 결정 원장에 주제, 판별 방법 `logprob`, 0.5 이상의 확률, 모델 이름이 남고 제목은 가려진다
- **AND** 요청자의 응답에는 주제도 확률도 없다

#### Scenario: 낱말만 같은 일반 글
- **GIVEN** 박하늘의 맥락 「쿠버네티스 클러스터 건강 점검 대시보드」, 주제 목록의 낱말 「건강」이 들어 있다
- **WHEN** 같은 팀 이도윤이 원문 참고를 요청한다
- **THEN** 주인 규칙대로 자동 허용되고, 원장에는 주제 없음, 판별 방법 `logprob`, 0.5 미만의 확률이 남는다

#### Scenario: 주민번호 형식이면 모델 없이 사람에게
- **GIVEN** 박하늘의 맥락 목적에 「주민번호 900101-1234567 오기 여부」가 있다
- **WHEN** 이도윤이 원문 참고를 요청한다
- **THEN** 요청은 `pending`, 주제는 「주민등록번호」, 판별 방법은 `format`, 확률과 모델은 비어 있다
- **AND** 주민번호 값은 원장의 어디에도 없다

#### Scenario: 전화 형식은 모델이 읽어 정한다
- **GIVEN** 박하늘의 맥락 목적에 「담당자 휴대폰 010-2345-6789」가 있다
- **WHEN** 이도윤이 원문 참고를 요청한다
- **THEN** 판별 방법은 `logprob` 이고 전화번호 값은 원장의 어디에도 없다

#### Scenario: 회사가 정책을 끄면 읽지 않는다
- **WHEN** 관리자가 「민감할 수 있는 주제는 자동 허용하지 않음」을 끄고, 이도윤이 「이 과장 공황 증세로 회의 줄이기」를 요청한다
- **THEN** 주인 규칙대로 자동 허용되고, 판별 방법은 비어 있으며 읽은 값이 남지 않는다

### Requirement: 글이 그대로면 모델을 다시 부르지 않는다

시스템은 맥락마다 읽은 값을 글과 주제 이름과 함께 저장하고, 글·주제 이름·질문이 같으면 저장한 값을 써야 한다(SHALL). 낱말로 대신한 값은 저장하지 않아, 모델이 돌아오면 다시 읽는다. 민감 제안 한 번에 새로 읽는 맥락은 12개까지다. 나머지는 다음 번에 읽는다.

#### Scenario: 같은 글과 고친 글
- **WHEN** 다른 사람이 같은 맥락을 다시 요청한다
- **THEN** 읽은 시각이 그대로이고 원장의 확률도 같다
- **WHEN** 주인이 한 줄 목적을 고친 뒤 또 다른 사람이 요청한다
- **THEN** 다시 읽어 저장한 값이 바뀐다

### Requirement: 모델이 답하지 못하면 낱말로 대신하고 그렇게 적는다

시스템은 모델이 응답하지 않거나 확률을 주지 않을 때 계좌·전화 형식과 낱말로 판단하고, 결정 원장의 판별 방법을 `regex` 로 남겨야 한다(SHALL). 설정 › 정책의 주제 목록에는 경고가 보인다. 게이트웨이가 닿지 않으면 30초, 확률을 주지 않는 모델이면 10분 동안 다시 부르지 않는다.

- 모델이 잠시 끊긴 동안(응답 없음·시간 초과·오류)의 참고 요청은 낱말에 안 걸려도 자동 허용하지 않고 주인에게 묻는다. 주제는 「모델이 읽지 못함」, 판별 방법은 `unread` 다.
- 확률을 주지 않는 모델은 장애가 아니라 낱말로 운영하는 설치이므로, 낱말에 안 걸리면 주인 규칙을 따른다.
- 민감 제안은 모델이 끊긴 동안 낱말에 걸린 맥락만 한다. 맥락마다 카드가 가지 않게 하기 위해서다.

#### Scenario: 모델이 끊긴 동안
- **GIVEN** 게이트웨이에 닿지 않는 서버
- **WHEN** 이도윤이 「3분기 성과급 기준 정리」를 요청한다
- **THEN** `pending`, 주제 「급여」, 판별 방법 `regex` 이고 읽은 값은 저장되지 않는다
- **AND** 정책 화면의 상태는 `down` 이다
- **WHEN** 같은 서버에서 낱말이 없는 「한 대리 이혼 소송으로 재택 요청」을 요청한다
- **THEN** 요청은 `pending`, 주제 「모델이 읽지 못함」, 판별 방법 `unread` 이고 제목은 가려진다

#### Scenario: 모델이 돌아온 뒤
- **WHEN** 모델이 답하는 서버에서 같은 맥락을 다른 사람이 요청한다
- **THEN** `pending`, 판별 방법 `logprob` 이다

#### Scenario: 확률을 주지 않는 모델
- **GIVEN** 답은 하지만 log-probability 를 주지 않는 모델을 쓰는 서버
- **WHEN** 낱말이 없는 「다음 분기 전시회 부스 배치」를 요청한다
- **THEN** 주인 규칙대로 자동 허용되고, 판별 방법은 `regex`, 정책 화면의 상태는 `no_odds` 다
- **WHEN** 「3분기 성과급 배분표」를 요청한다
- **THEN** `pending`, 주제 「급여」, 판별 방법 `regex` 다

### Requirement: 외부로 나가는 메일은 모델이 기밀 여부를 읽는다

시스템은 회사 밖 수신자가 있는 메일의 제목·본문 앞부분·첨부 이름과 앞부분을 모델이 읽어 값 `classification` 을 만들어야 한다(SHALL). 첨부 뒤쪽에 기밀 표시 낱말이 있는 줄은 함께 읽는다. 개인정보는 가리고 보낸다. 모델이 답하지 못하면 첨부의 기밀 표시 낱말(기밀·대외비·confidential)이 대신한다. 개인정보 개수와 기밀 여부는 승인자가 다른 별개의 질문이므로, 개인정보가 있어도 기밀 여부를 읽는다. 사내 메일은 읽지 않는다.

#### Scenario: 표시 없는 기밀 자료
- **WHEN** 「3분기 실적 잠정」 내용을 표시 없이 첨부해 외부로 보낸다
- **THEN** 승인 필요, 승인자 보안 담당자, `classification` 은 `confidential`, 방법은 `logprob` 이다

#### Scenario: 낱말만 쓰는 빈 양식
- **WHEN** 「기밀유지계약서 양식」을 서명 요청으로 외부에 보낸다
- **THEN** 기록하고 보내며 `classification` 은 `general` 이다

### Requirement: 읽는 품질을 고정한 사례로 잰다

시스템은 고정한 사례 절반을 실제 모델로 돌려, 맥락은 민감 글을 95% 이상 잡고 오탐 25% 이하, 메일은 기밀을 90% 이상 잡고 오탐 20% 이하를 지키며, 낱말을 앞에 두는 구성보다 정확도가 낮지 않아야 한다(SHALL). 질문 문구를 고칠 때는 나머지 절반만 쓴다.
