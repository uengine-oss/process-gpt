# 딥 에이전트 대화로 프로세스 만들기 명세

## Purpose
첫 화면 입력창에서 딥 에이전트에게 프로세스를 만들어 달라고 했을 때, 사용자가 초안을 승인하고 추가 항목을 고르는 흐름이 한 번의 응답으로 끝나고, 사용자가 고른 것만 만들어지며, 답에는 사용자에게 하는 말만 남도록 보장한다.

## 용어
- **초안 질문**: 「이대로 진행할까요? 추가하거나 바꿀 단계가 있으면 알려주세요.」로 묻는 승인/반려 질문.
- **후보 질문**: 「이 프로세스에 추가할 항목을 골라주세요 (안 고르면 건너뜁니다)」로 스킬 · 에이전트 · DMN 후보를 보이는 선택 질문.
- **서브에이전트**: 딥 에이전트가 일을 나눠 맡기는 하위 에이전트(예: 스킬 작성 담당).

## Requirements

### Requirement: 에이전트 고르기는 실행 엔진을 함께 밝힌다
시스템은 첫 화면 입력창의 에이전트 고르기에 「기본 에이전트 (LangChain ReAct)」, 「딥 에이전트 (LangGraph)」, 「딥 에이전트 (Codex)」 세 가지를 SHALL 보이고, 새 대화의 기본값은 「딥 에이전트 (LangGraph)」로 SHALL 둔다.

#### Scenario: 고르기를 연다
- **WHEN** 사용자가 첫 화면 입력창의 에이전트 고르기를 연다
- **THEN** 「기본 에이전트 (LangChain ReAct)」 · 「딥 에이전트 (LangGraph)」 · 「딥 에이전트 (Codex)」가 이 순서로 보인다
- **AND** 고르기 전 값은 「딥 에이전트 (LangGraph)」다

### Requirement: 딥 에이전트로 2단계 프로세스를 끝까지 만든다
시스템은 딥 에이전트에게 단계 · 담당 · 폼을 말로 설명한 프로세스 생성 요청을 받으면, 초안 질문과 후보 질문을 거쳐 결과 전달을 보류하지 않고 「프로세스를 생성했어요. 확인 후 저장 버튼을 눌러주세요.」로 SHALL 끝낸다. 작업 폴더에는 흐름도(`.bpmn`)가 SHALL 남는다.

#### Scenario: 3장 프롬프트
- **GIVEN** 「영업 제안서 작성 프로세스를 만들어 줘. 고객이 요청사항을 입력하면 영업 담당자가 제안서를 작성해서 고객에게 전달하는 2단계 프로세스야. 단계마다 입력 폼도 만들어 줘.」
- **WHEN** 사용자가 초안을 승인하고 후보 질문을 건너뛴다
- **THEN** 1~4분 안에 생성 완료 안내가 나오고 「결과 전달을 보류했어요」는 나오지 않는다
- **AND** 작업 폴더에 「영업 제안서 작성 프로세스.bpmn」이 있고 「저장」 단추가 보인다

### Requirement: 후보를 하나도 고르지 않으면 만들지 않는다
시스템은 후보 질문에 사용자가 아무것도 고르지 않으면(건너뛰기 또는 빈 제출) 스킬 · 에이전트 · DMN을 하나도 SHALL NOT 만들고, 폼과 참조정보는 그대로 SHALL 만든다.

#### Scenario: 건너뛰기
- **GIVEN** 후보 질문에 스킬 2개와 에이전트 1개가 보인다
- **WHEN** 사용자가 「건너뛰기」를 누른다
- **THEN** 작업 폴더에 새 스킬 · 에이전트 파일이 생기지 않는다
- **AND** 생성 완료 안내에 스킬 · 에이전트를 만들었다는 말이 없다

### Requirement: 답에는 사용자에게 하는 말만 남는다
시스템은 서브에이전트가 딥 에이전트에게 돌려주는 결과(예: `created: /workspace/…/SKILL.md`)를 사용자에게 보이는 답이나 저장된 대화에 SHALL NOT 넣는다.

#### Scenario: 스킬을 고른다
- **GIVEN** 사용자가 후보 질문에서 스킬 하나를 고른다
- **WHEN** 딥 에이전트가 스킬 작성 서브에이전트에게 맡겨 스킬을 만든다
- **THEN** 마지막 답은 「created:」로 시작하지 않고 작업 폴더 경로를 늘어놓지 않는다

### Requirement: 한 번 답한 질문은 다시 열리지 않는다
시스템은 사용자가 답한 초안 질문 · 후보 질문을 「제출함」으로 SHALL 보이고, 같은 질문의 「응답 제출」을 다시 열어 SHALL NOT 두지 않는다. 사용자가 답한 뒤 같은 질문의 본문이 서버에서 다시 도착해도 마찬가지다.

#### Scenario: 승인한 뒤
- **GIVEN** 사용자가 초안 질문에 「승인」을 보냈다
- **WHEN** 딥 에이전트의 다음 답과 서버에 저장된 질문 본문이 차례로 도착한다
- **THEN** 화면에 열린 초안 질문 패널이 없다
- **AND** 대화에 「승인」은 한 번만 있다
