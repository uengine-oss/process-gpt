## Requirements
### Requirement: 네트워크 접속 없는 번들 시스템 스킬 로딩

deepagents 서비스는 process-gpt가 직접 제공하는 시스템 스킬을 어떠한 외부 네트워크 접속(Git 원격 저장소 fetch 등)도 없이 로딩할 수 있어야 한다(SHALL). 번들 시스템 스킬은 서비스 배포 이미지에 포함된 로컬 콘텐츠만으로 구성되며, 서비스 기동 시점과 이후 채팅 실행마다 최신 상태로 동기화되어야 한다(SHALL).

#### Scenario: 인터넷 접속이 차단된 환경에서 기동
- **WHEN** deepagents 서비스가 외부 인터넷 접속이 전혀 없는 폐쇄망 환경에서 기동하면
- **THEN** 번들 시스템 스킬이 오류 없이 로딩되어 스킬 목록에 나타난다

#### Scenario: 재기동 후 즉시 조회 가능
- **WHEN** deepagents 서비스가 재기동을 완료하면
- **THEN** 아직 어떤 채팅도 시작되지 않은 상태에서도 스킬 목록 조회 API에서 번들 시스템 스킬이 확인된다

### Requirement: 모든 테넌트에 대한 전역 노출

번들 시스템 스킬은 개별 테넌트의 업로드 동작과 무관하게, 시스템에 등록된 모든 테넌트에서 공통으로 사용 가능해야 한다(SHALL). 테넌트가 스킬을 업로드한 이력이 전혀 없어도 번들 시스템 스킬은 해당 테넌트의 스킬 목록과 채팅에서 사용할 수 있어야 한다(SHALL).

#### Scenario: 스킬을 한 번도 업로드하지 않은 테넌트
- **WHEN** 스킬을 한 번도 업로드한 적 없는 테넌트가 스킬 목록을 조회하면
- **THEN** 번들 시스템 스킬이 해당 테넌트의 목록에 자동으로 포함되어 있다

#### Scenario: 별도 설정 없이 채팅에서 즉시 사용
- **WHEN** 사용자가 채팅에서 번들 시스템 스킬의 트리거 조건에 해당하는 요청을 보내면
- **THEN** 에이전트는 해당 테넌트가 그 스킬을 별도로 업로드하거나 연결하지 않았어도 스킬 내용을 참고해 응답한다

### Requirement: 테넌트 업로드 스킬과의 격리 및 우선순위

번들 시스템 스킬은 테넌트별 업로드 스킬의 저장 위치와 격리되어야 하며(SHALL), 테넌트가 번들 시스템 스킬과 동일한 이름의 스킬을 직접 업로드한 경우에는 테넌트가 업로드한 버전이 우선 적용되어야 한다(SHALL).

#### Scenario: 테넌트가 동일 이름으로 커스터마이징
- **WHEN** 테넌트가 번들 시스템 스킬과 같은 이름으로 자신만의 스킬을 업로드하면
- **THEN** 해당 테넌트의 채팅에서는 테넌트가 업로드한 버전이 사용된다

#### Scenario: 다른 테넌트의 업로드 스킬은 노출되지 않음
- **WHEN** 한 테넌트가 자신만의 전용 스킬을 업로드하면
- **THEN** 다른 테넌트의 스킬 목록에는 그 전용 스킬이 나타나지 않고, 번들 시스템 스킬만 공통으로 나타난다

### Requirement: 기존 Git 기반 전역 컬렉션과의 공존

번들 시스템 스킬 제공 경로는 기존의 Git 원격 저장소 기반 전역 스킬 컬렉션 제공 경로와 독립적으로 동작해야 한다(SHALL). Git 원격 저장소 접속이 실패하는 경우에도 번들 시스템 스킬의 제공은 영향을 받지 않아야 한다(SHALL).

#### Scenario: Git 원격 저장소 접속 실패
- **WHEN** Git 기반 전역 스킬 컬렉션의 원격 저장소 접속이 실패하면
- **THEN** 해당 Git 기반 컬렉션은 비어 있을 수 있지만, 번들 시스템 스킬은 계속 정상적으로 제공된다
