### D-1111-02 휴대폰에서도 기본은 데스크톱 화면이다
- **결정**: 휴대폰 브라우저로 열어도 간소화한 모바일 화면 대신 데스크톱 화면을 띄운다. 앱 화면에 처음 들어오면 라이트 버전(휴대폰 간소화 화면)을 쓸지 팝업으로 묻는다. 한 번 답하면 다시 묻지 않고, 설정에서 바꿀 수 있다고 알려 준다.
- **세부(위임 판단)**:
  - 데스크톱 화면은 브라우저의 「데스크톱 사이트 요청」처럼 화면 폭을 1280px로 그린 뒤 휴대폰 화면에 맞춰 줄인다(두 손가락으로 확대). 화면마다 휴대폰용 분기를 고치지 않는다.
  - 라이트 버전은 기존 휴대폰 화면이다. 설정 › 테마 설정 「휴대폰 화면」에서 바꾼다.
  - 답은 해당 기기(브라우저)에 저장한다. 화면 폭은 로그인 전에 정해야 하므로 계정에 저장할 수 없다. 다른 휴대폰에서는 다시 묻는다.
  - 랜딩 · 로그인 · 외부 폼은 입력하기 쉽도록 휴대폰 폭을 유지한다. 로그인한 뒤 앱 화면으로 갈 때 한 번 새로 연다.
  - 휴대폰 판단: 터치 화면이면서 짧은 변이 768px 이하. 태블릿 대부분은 원래 데스크톱 화면이다.
  - 네이티브 앱(process-gpt-mobile)과 PAL · uEngine 모드는 그대로 둔다.
- **함께 고친 결함**: 없는 아이콘 파일을 불러오면 서버가 돌려준 index.html이 화면에 끼어들어 휴대폰 화면 폭을 되돌렸다(사이드바 「온톨로지 데이터」 아이콘). SVG가 아니면 그리지 않게 했다.

### D-1111-05 에이전트에 맡긴 결과에 요약을 붙인다

- **세부(위임 판단)**: 딥 에이전트가 폼 값과 함께 2~3문장으로 요약을 쓰고, 실행기는 요약을 따로 떼어 작업 이벤트로만 보낸다. 요약은 폼 값이 아니므로 업무 데이터 · 프로세스 변수에 저장하지 않는다. 다시 열어도 보인다.
- **상태**: 반영 — deepagents #12, vue3 #247

### D-1111-06 맡긴 업무에 필요한 전문 에이전트를 스스로 골라 붙인다(팀 구성)
- **결정**: 「이런 스마트한 티밍 단계가 있는가?」에 대한 답은 「없었다」이다. 기존 기능을 재사용해 팀 구성 단계를 새로 둔다. 기본으로 딥 에이전트에 맡기고, 꼭 필요할 때만 에이전트 프로필(스킬 · MCP 묶음)을 서브 에이전트로 붙인다.
- **세부(위임 판단)**:
  - 프로세스 설계자가 해당 단계의 에이전트 · 도구를 정해 두지 않은 업무에서만 고른다. 정해 둔 팀은 그대로 쓴다.
  - 후보는 같은 회사의 에이전트 프로필(스킬 · MCP 묶음)이다. 다른 방식의 에이전트(a2a 등)는 뺀다.
  - LLM이 한 번 고른다(최대 3개). 채팅방 라우터는 거의 늘 누군가를 고르지만, 여기서는 그 스킬 · 도구가 꼭 필요할 때만 고른다. 필요 없으면 혼자 처리한다.
  - 고른 뒤 실제로 맡길지는 딥 에이전트가 일하면서 정한다. 화면의 「팀 구성」 카드에 누구를 왜 골랐는지(또는 혼자 처리) 남긴다.
  - 확인(설치본): 제안서 파일이 필요한 업무에서는 「제안서 문서 작성 에이전트」만 골라 실제로 맡겼다. 고객 요청 입력 업무에서는 혼자 처리했다.
- **함께 고친 결함**: 이전 단계 입력이 짧아 그대로 전달됐는데도 「파일로 저장되었다」고 안내해, 에이전트가 없는 파일을 찾다가 결과 없이 끝났다.
- **상태**: 반영 — deepagents #12(모든 테넌트에 함께 적용, 끄는 설정 DEEPAGENTS_AUTO_TEAM=0)

### D-1111-07 휴대폰에서는 「내 일」만 처리한다
- **결정**: 휴대폰 사용성 점검(별도 에이전트, 화면안 7개) 결과에 따라 진행한다. 휴대폰에는 할 일 · 진행 · AI · 알림 · 나만 남기고, 관리 기능은 아예 두지 않는다(「모바일에서는 모든 기능을 사용할 필요가 없어. 특히 관리자 기능은 아예 필요가 없고」, 「준 안대로 구현 진행해」).
- **세부(위임 판단)**:
  - 1단계: 휴대폰(라이트 버전)에서 관리 · 설계 · 분석 메뉴를 숨기고, 주소로 들어와도 「PC에서 열어 주세요」 안내 화면으로 보낸다. 관리자도 휴대폰에서는 같은 화면을 본다. 바로 고칠 결함 세 가지(휴대폰에서 숨겨진 에이전트에 맡기기, 저장되지 않던 AI 초안, 미리 선택돼 있던 「승인」)도 고친다.
  - 2단계: 하단에 탭 다섯 개가 있는 화면을 만든다. 저장소에 이미 있는 휴대폰 앱(mobile/)을 쓸 수 있는지 하루 동안 확인한 뒤 방식을 정한다.
  - 휴대폰 기본 화면은 새 화면을 적용한 뒤 라이트 버전으로 바꾸고, 「나」 탭에 「PC 화면으로 보기」를 둔다. 그때 D-1111-02(데스크톱 기본)를 뒤집는다.
- **2단계 방식(위임 판단)**: 저장소의 휴대폰 앱(mobile/)을 휴대폰 웹(/m/)으로 쓴다(A안). 하루 확인에서 고치지 않고 브라우저에서 돌았고, 서빙은 약 60줄, 첫 로딩은 포털의 7MB 이상 대신 약 1.5MB다. 지금 화면을 손보는 B안과 일수는 비슷하지만 PC 화면 회귀 위험이 작다.
- **상태**: 1단계 vue3 #248, 2단계 vue3 #249(아래 탭 다섯 칸 · 업무 상세 · 승인 화면 · 진행 타임라인 · 알림 · 나, 휴대폰 기본을 휴대폰 웹으로). 남은 것: 반려 · 승인 · 에이전트 완료 알림은 서버가 아직 만들지 않음, AI 답의 할 일 카드, Word · HWPX 미리보기, 실제 휴대폰 확인


### D-1111-08 휴대폰 웹의 로그인 · 2단계 인증은 포털이 맡는다
- **결정(위임 판단, 보안)**: #249 배포 직후 휴대폰 웹(/m/)에서 2단계 인증(TOTP)을 건너뛰는 문제를 찾았다. 휴대폰 웹은 자기 이메일 · 비밀번호 로그인과 세션 유무만 확인했고, 포털 라우터도 MFA 게이트보다 먼저 휴대폰 웹으로 옮겼다. 이 때문에 2단계 인증을 등록한 계정이 비밀번호만으로 할 일 · 업무를 열 수 있었다. 소셜 로그인 사용자는 휴대폰 웹에 로그인할 수 없었다. 이렇게 바꾼다.
  - 휴대폰 웹에는 로그인 화면을 두지 않는다. 포털과 같은 판정(utils/mfaGate)으로 포털의 로그인 · 2단계 인증 · 등록 화면으로 보낸다.
  - 포털은 MFA 게이트를 통과한 뒤에만 휴대폰 웹으로 옮긴다.
  - 계정 설정은 휴대폰에서도 포털에 둔다. 등록 화면과 휴대폰 웹 사이를 계속 오가지 않게 하기 위해서다.
- **세부**: 네이티브 앱(mobile/ Capacitor)에는 아직 2단계 인증 화면이 없다. 그래서 2단계 인증이 필요한 계정은 로그아웃시키고 웹 포털을 쓰라고 안내한다. 전에는 비밀번호만으로 들어갈 수 있었다.
- **상태**: vue3 #250. VM에서 고치기 전 우회를 재현했다(F-MV-14 실패). 고친 뒤 F-MV-01~14 12개와 단위 31개가 통과했다.

### D-1110-01 상단 「나의 업무」 메뉴를 없앤다
- **결정**: 데스크톱 상단의 「나의 업무」를 보이지 않게 한다. 기능과 `/todolist` 주소는 남긴다.
- **대신**: 사이드바 「인스턴스」에서 지금 내가 처리할 업무가 있는 인스턴스에 표시(「내 업무 N」)를 붙인다. 사용자는 인스턴스에 들어가 업무를 확인한다.
- **이유**: 「나의 업무」에는 할 일이 너무 많이 쌓여 실제로는 쓰지 않는다. 자신의 업무는 인스턴스 안에서 확인하면 된다.
- **세부(위임 판단)**: 표시에는 「나의 업무」의 진행 중·보류/반송 영역과 같은 업무의 수를 집계한다(IN_PROGRESS · SUBMITTED · PENDING). 예정 업무(TODO)는 집계하지 않는다. 휴대폰 사이드바의 할 일 항목은 남긴다(휴대폰에서는 이 항목이 주 화면이다).
- **상태**: 반영 — 운영 배포 완료(vue3 #241 · #242, 11-10)

### D-1110-02 에이전트 고르기에 엔진 이름을 밝힌다

### D-1110-03 「컴포넌트」라는 말을 쓰지 않는다
