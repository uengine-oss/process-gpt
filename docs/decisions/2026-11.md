## 2026-11-11 — 튜토리얼 영상 검토와 휴대폰 화면

- 반영: process-gpt-vue3 #244 · #245, 스펙 `openspec/specs/gateway_mobile-web-access`, 튜토리얼 2장 · 18장

### D-1111-01 페이지 머리 배치를 다른 화면과 맞춘다
- **결정**: 프로세스 체계도 화면의 제목 · 부제 · 단추가 카드 테두리에 붙지 않게 한다. 조직도 · 스킬 관리처럼 여백을 두고, 단추는 제목과 같은 줄 오른쪽에 둔다.
- **확인한 원인**: 이 화면은 PAL 공통 디자인의 머리 형식을 쓰지만, 해당 스타일은 PAL 모드에서만 불러온다. *.process-gpt.io(비 PAL)에는 스타일 정의가 없어 여백이 0이었다. 「프로세스 변경 관리」 · 「알림」 화면도 같았다.
- **세부(위임 판단)**: 화면마다 고치지 않고 비 PAL 모드의 공통 머리 형식을 한 곳에서 보완한다(PAL 화면은 그대로). 튜토리얼 2장의 그림과 영상을 다시 만든다.
- **상태**: PR #244 — 설치본(VM)에서 확인(회귀 F-UX-17), 운영 병합 대기

### D-1111-02 휴대폰에서도 기본은 데스크톱 화면이다
- **결정**: 휴대폰 브라우저로 열어도 간소화한 모바일 화면 대신 데스크톱 화면을 띄운다. 앱 화면에 처음 들어오면 라이트 버전(휴대폰 간소화 화면)을 쓸지 팝업으로 묻는다. 한 번 답하면 다시 묻지 않고, 설정에서 바꿀 수 있다고 알려 준다.
- **세부(위임 판단)**:
  - 데스크톱 화면은 브라우저의 「데스크톱 사이트 요청」처럼 화면 폭을 1280px로 그린 뒤 휴대폰 화면에 맞춰 줄인다(두 손가락으로 확대). 화면마다 휴대폰용 분기를 고치지 않는다.
  - 라이트 버전은 기존 휴대폰 화면이다. 설정 › 테마 설정 「휴대폰 화면」에서 바꾼다.
  - 답은 해당 기기(브라우저)에 저장한다. 화면 폭은 로그인 전에 정해야 하므로 계정에 저장할 수 없다. 다른 휴대폰에서는 다시 묻는다.
  - 랜딩 · 로그인 · 외부 폼은 입력하기 쉽도록 휴대폰 폭을 유지한다. 로그인한 뒤 앱 화면으로 갈 때 한 번 새로 연다.
  - 휴대폰 판단: 터치 화면이면서 짧은 변이 768px 이하. 태블릿 대부분은 원래 데스크톱 화면이다.
  - 네이티브 앱(process-gpt-mobile)과 PAL · uEngine 모드는 그대로 둔다.
- **함께 고친 결함**: 없는 아이콘 파일을 불러오면 서버가 돌려준 index.html이 화면에 끼어들어 휴대폰 화면 폭을 되돌렸다(사이드바 「온톨로지 데이터」 아이콘). SVG가 아니면 그리지 않게 했다.
- **상태**: PR #245 — 설치본에서 회귀 F-MV-01~07 통과(휴대폰 에뮬레이션), 실제 휴대폰 확인과 운영 병합 대기

### D-1111-03 홈 화면에 추가(웹앱)를 둔다
- **결정**: 휴대폰 홈 화면에 웹페이지를 앱처럼 등록하는 기능을 둔다.
- **세부(위임 판단)**: 앱 이름은 「Process GPT」, 아이콘은 로봇이다. 단추는 휴대폰 화면 질문 창과 설정 › 테마 설정에 둔다. 안드로이드 크롬 등에서는 브라우저 설치 창을 띄우고, iPhone(Safari)에서는 설치 창을 띄울 수 없어 공유 단추 › 「홈 화면에 추가」를 안내한다. 홈 화면 아이콘을 누르면 정의 체계도가 열린다. 오프라인 캐시(서비스 워커)는 두지 않는다. 배포 뒤 옛 화면이 남을 위험을 피하기 위해서다.
- **상태**: PR #245 — 운영 병합 대기

### D-1110-01 상단 「나의 업무」 메뉴를 없앤다
- **결정**: 데스크톱 상단의 「나의 업무」를 보이지 않게 한다. 기능과 `/todolist` 주소는 남긴다.
- **대신**: 사이드바 「인스턴스」에서 지금 내가 처리할 업무가 있는 인스턴스에 표시(「내 업무 N」)를 붙인다. 사용자는 인스턴스에 들어가 업무를 확인한다.
- **이유**: 「나의 업무」에는 할 일이 너무 많이 쌓여 실제로는 쓰지 않는다. 자신의 업무는 인스턴스 안에서 확인하면 된다.
- **세부(위임 판단)**: 표시에는 「나의 업무」의 진행 중·보류/반송 영역과 같은 업무의 수를 집계한다(IN_PROGRESS · SUBMITTED · PENDING). 예정 업무(TODO)는 집계하지 않는다. 휴대폰 사이드바의 할 일 항목은 남긴다(휴대폰에서는 이 항목이 주 화면이다).
- **상태**: 반영 — 운영 배포 완료(vue3 #241 · #242, 11-10)

### D-1110-02 에이전트 고르기에 엔진 이름을 밝힌다
- **결정**: 「기본 에이전트 (LangChain ReAct)」 · 「딥 에이전트 (LangGraph)」 · 「딥 에이전트 (Codex)」로 쓴다. 기본값은 딥 에이전트 (LangGraph)이다.
- **이유**: 코덱스도 딥 에이전트의 하나이다. 이름만 보면 모델을 고르는 것처럼 보이고, 딥 에이전트와 코덱스가 같은 줄에 있으면 무엇이 다른지 알 수 없다. 시작할 때마다 에이전트 실행 환경을 선택할 수 있는 것은 괜찮지만 이름을 정확히 적는다.
- **상태**: 반영 — 운영 배포 완료(#241)

### D-1110-03 「컴포넌트」라는 말을 쓰지 않는다

### D-1110-04 딥 에이전트로 프로세스를 만들 때 문제가 없어야 한다
- **결정**: 튜토리얼이 「딥 에이전트는 결과 전달을 보류할 수 있으니 기본 에이전트로 만들라」고 안내하게 된 문제의 원인을 해결한다. 그 뒤 튜토리얼을 딥 에이전트(기본값)로 다시 만든다.
- **확인한 원인**: 운영 중인 deepagents(master)에는 튜토리얼 촬영 중 수정한 PR 10개(#1~#10)가 반영되지 않았다. 수정한 버전에서는 3장 프롬프트로 3번 모두 생성이 끝까지 완료되었다. 그 과정에서 추가로 발견해 수정한 문제는 두 가지이다: 서브에이전트의 생성 확인 메시지(「created: …/SKILL.md」)가 답변 앞에 붙는 문제, 후보를 하나도 선택하지 않았는데도 스킬을 만드는 문제.
- **세부(위임 판단)**: 10개 PR과 추가 수정 사항을 한 번에 병합해 운영에 배포한다(공용 서비스라 Lite와 모든 테넌트에 함께 반영된다).
- **상태**: 반영 — deepagents #11(9e05489) 운영 배포, 답한 질문 패널 수정 vue3 #243. 설치본(VM)에서 3장 프롬프트 생성 완료(48~65초, 보류 0)
